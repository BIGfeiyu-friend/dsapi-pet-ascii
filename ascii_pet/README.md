# ASCII 字符画桌宠（pet_ascii）

> 这是开发说明和变更记录。怎样安装、需要什么，见仓库根目录的 `README.md`。下文里的“你”指桌宠的主人（使用者）。

由 DeepSeek 驱动、能自主创作字符画表情与动作的桌宠视觉模块。

**设计原则：AI 负责想象和创造，程序负责保持结构、连续性与流畅播放。**

- **画面**：默认角色是女仆插画，由两张同构图生成：无五官版作为底图，有五官版提供默认五官。整幅转换成高密度彩色字符画，画法沿用《world.search(you)》MV 的字符引擎：OCR-A 字体、亮度到字符的梯度、逐字着色、同色衬底和字符流纹理。
- **面部骨架（类似 Live2D）**：五官不再让模型逐字画字符，而是由本地骨架按原画风格在像素级绘制，再走与身体完全相同的字符化流程。因此眼睛、嘴巴的位置、比例和配色永远与原画一致。
- **AI 的工作**：AI 设计表情，包括组合 30 个预设与连续参数、左右眼不对称、瞳孔形状、泪、汗、脸红、多帧节奏，并编排身体动作、特效和字符演出。
- **与对话联动**：桌宠主模型在每次回复开头顺带输出一个表情标签。标签被实时剥离，本地立即演出，不需要额外请求 API；说话期间嘴巴会动。
- **自创表情（v0.3）**：主模型觉得现有表情都不贴切时，可以在标签里用 `new=名字` 当场设计一个新表情，存入表情库，以后直接按名字复用。另外，后台的“表情进化”会定期回顾最近的对话、每个表情的使用次数和你的 👍/👎，再“照镜子”看看表情实际画出来的样子，让副模型（开启思考）新建、修改、合并或淘汰表情。每次修改都保留版本，可以回滚（v0.4）。
- **说完之后（v0.3，v0.8.1 改为至少 1 分钟后）**：主模型在每次回复的表情标签里同时决定，说完之后要不要换成别的表情进入挂机、在 1 分钟之后再等几秒（0~240 秒）；也可以保持当前表情。
- **窗口（v0.3）**：默认是不透明的深色小窗口，带标题栏、圆角和阴影，背后的桌面不会再透过画面；旧的透明悬浮样式仍可在右键菜单中切换。
- **“AI 对话”窗口换皮肤**：字符画风格（v0.5.1），或 LINE 风格（v1.4.0：蓝天背景、白 / 绿圆角气泡、她的笑脸头像、时间和「既読」、“Aa” 输入框），也可以保持桌宠原样，右键菜单里三选一。
- **自主创作（v0.7）**：她不只是调眼睛、嘴的参数，而是会**发明**：
  - 用绘图图元设计全新的五官和装饰部件（数据，不是代码）；
  - 移动、缩放、旋转、隐藏、新增脸上的节点；
  - 暂时脱离角色做全画布的自由字符画演出。

  每个候选都会在本地真实渲染，并做确定性检查（越界、遮挡、结构、字符画上是否看得见）。全新部件和骨架改造会在后台请看图模型评价截图（只作参考）。她看到实际结果后自己决定修改、采用或放弃。实验记录、失败原因、视觉评价和她自己的创作心得都会存下来。各种风格轮流探索，每种风格的代表作受保护，避免收敛成一种风格。
- **睡眠模式（v0.6）**：超过 30 分钟没有互动，她会犯困、睡着。睡眠动画完全由本地预设即时编排，不调用 API：每口呼吸长短不同，梦境情绪会慢慢变换，梦话、鼻涕泡、叹气、眼皮跳等小事件随机穿插，所以不像在“播片”。睡着时在对话里给她发消息，会随机播放 6 种吵醒反应之一。
- **副人格（v0.9，先跑影子模式）**：她睡着时做一次“夜间回顾”，看看最近和你的相处里有没有慢慢形成的稳定倾向（说话习惯、兴趣、相处方式、情绪倾向等），写成第一人称的一句话提议。提议依次经过：
  - 程序核对证据：按编号取回原话，逐字比对；
  - 规则审查；
  - 另一个模型的独立审核。

  证据攒够、审核通过、没超过速度上限，提议才生效。你写的人设（正典）她无权改动。现在是**影子模式**：管线完整运行，但条目不进提示词，只在测试台「人格」页给你看。详见 3.18 和 `docs/persona_evolution_design.md`。
- **虚拟房间（v1.0）**：她有一个属于自己的小文件夹。没有人给她布置任务，什么时候进去、在里面写什么、画什么、整理什么、要不要给你留便条、还是什么都不做，全由她自己决定。桌宠运行时她就会自己进去，和你开没开“房间”窗口无关。你从单独的“房间”窗口（双击 `ascii_pet\open_room.bat`，或自己建一个快捷方式）打开一扇**单向玻璃**：看她的状态、房间里的文件、每一步的想法和思考过程、她的房间记忆，也可以往「礼物」文件夹里送东西。房间记忆和桌宠本体的记忆分开存放，也不影响副人格；但两边是打通的（v1.1）：聊天时她记得房间里的事，在房间里她也记得和你聊过什么。详见 3.19。
- **本地引擎**：负责逐帧播放、参数补间、眨眼、视线、特效和背景。等待 API 时动画不会停。

## 1. 快速开始

### 方式 A：用桌宠自带的运行环境（推荐，无需安装 Python）

在本文件夹中双击：

- `open_lab.bat`：打开**开发测试台**
- `open_pet.bat`：打开**桌宠窗口**

也可以在命令行运行：

```
dsh-pet-standalone-webm-chat.exe --ascii-lab           # 开发测试台
dsh-pet-standalone-webm-chat.exe --ascii-pet           # 桌宠窗口
dsh-pet-standalone-webm-chat.exe --ascii-lab --mock    # 不调用 API（Mock）
```

这两个参数只会启动字符画模块，不会再开一个原来的桌宠。

### 方式 B：随桌宠启动，并与聊天联动

1. 在测试台「显示与设置」页勾选「随桌宠启动字符画窗口，并与对话联动」（对应配置项 `attach_to_pet: true`）。
2. 重启桌宠。

默认联动方式是 `chat_link: "inline"`（见第 3.8 节），流程如下：

1. 模块在聊天的系统提示末尾加一段固定的表情说明。它固定不变，可以命中前缀缓存。
2. 主模型每次回复都以类似 `<face happy level=0.8 blush=0.6 act=bounce fx=sparkle idle=smile after=3>` 的标签开头，约 20~30 个 token。
3. 标签在流式输出中被剥离。聊天窗口、对话气泡、语音朗读、会话记录和永久记忆都看不到它。
   - 正因为会话记录里她以前的回复都没有标签，真实对话的长历史会让模型照着省略标签。
   - 所以每轮在用户消息末尾附一句提醒：`〔回复照常以表情标签开头：<face 表情 … idle=… after=…>〕`。
   - 提醒只出现在发给 API 的请求里，见第 3.8 节。
4. 表情在回复刚开始时就切换。流式输出期间，嘴巴跟着动。
5. 如果某次回复没带标签，就按回复里的关键词在本地兜底（不调用 API）。

其它联动方式：

- `ai`：回复结束后另起一次表情生成请求。可以自由创作多帧演出，但较慢，也会额外计费。
- `local`：只用本地关键词。
- `off`：不联动。

### 方式 C：独立 Python 环境

需要 Python 3.10 以上，并安装 `PySide6`；转换素材还需要 `Pillow`。

```
pip install PySide6 Pillow
cd ascii_pet
python -m pet_ascii           # 桌宠窗口
python -m pet_ascii --lab     # 测试台
python -m pet_ascii --mock    # Mock 模式
```

## 2. 配置

配置文件位于 `%APPDATA%\dsh-pet-standalone-webm-chat\ascii_pet\config.json`，首次运行时自动生成，修改后重启生效。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `model` | `deepseek-flash` | DeepSeek 官方当前模型名（V4.1 Flash）；可改为 `deepseek-v4-pro` |
| `base_url` | 空 | 留空则沿用桌宠聊天设置里的地址，再不行就用 `https://api.deepseek.com` |
| `api_key` | 空 | 留空时按下面的顺序自动查找 |
| `temperature` / `max_tokens` / `timeout` | 0.9 / 2600 / 45 | 生成参数 |
| `disable_thinking` | true | 关闭 DeepSeek 默认开启的思考模式（快很多） |
| `retries` | 1 | 输出不合规时，带着校验错误让模型修正重试的次数 |
| `min_interval_s` | 4 | 两次 API 调用之间的最小间隔 |
| `dedupe_window_s` | 20 | 这段时间内的同义请求会被忽略 |
| `reuse_probability` | 0.3 | 命中相似缓存时直接复用旧动画的概率，其余情况仍会生成新的 |
| `daily_request_limit` / `daily_token_limit` | 300 / 400000 | 每日预算；超出后只复用缓存或用本地程序生成 |
| `autonomous` | false | 自主表达：空闲时偶尔自己做个小动作（会调用 API） |
| `autonomous_min_s` / `autonomous_max_s` / `autonomous_daily_limit` | 240 / 720 / 40 | 自主表达的冷却时间与每日次数 |
| `attach_to_pet` | false | 是否随桌宠启动并联动对话 |
| `chat_link` | `inline` | `inline`：主模型回复开头顺带输出表情标签（推荐）；`ai`：另起一次表情生成；`local`：本地关键词；`off`：不联动 |
| `inline_reminder` | true | 每轮在用户消息末尾提醒“以表情标签开头”。关掉后，真实对话里模型大多会省略标签：实测 1/8，开着时 20/20 |
| `character` | `maid_bust` | `maid_bust` 为女仆特写，脸大，表情最清楚；`maid` 为半身，带桌子和米饭；`shenshen_bust` / `shenshen` 为旧角色（没有面部骨架） |

| `background` | `none` | 背景：`none` / `log` / `code` / `rain` / `noise` |
| `code_rows` | true | MV 风格：身体每 4 行嵌入一行滚动字符流（内容是 AI 的 `think` 独白） |
| `plate_mode` | `tint` | 字符衬底：`tint` 用同色压暗做底（彩色字符块效果）；`solid` 统一暗底；`none` 不画 |
| `window_style` | `framed` | `framed`：不透明窗口，带标题栏；`floating`：旧的透明悬浮样式 |
| `trim_unused_menu` | true | **去掉用不到的原桌宠菜单项**（v1.3.6）：播放动画、切换角色、播放速率、音乐、桌宠控制、快捷启动、工具与帮助、Agent 联动、主动识屏、待办提醒、彩蛋「厉害了我的鲸」。只看顶层菜单，改成 false 并重启即恢复。详见 3.21 |
| `remove_spawn_pet` | true | **删去“生小肥鱼”**：不再生成小肥鱼（`AppShell.spawn_pet` / `spawn_in_process_window` 换成什么都不做）；右键菜单去掉「生小肥鱼」「退出子肥鱼」；桌宠设置里隐藏“生小肥鱼”一组，以及「菜单」页布局编辑器（结构和实时预览）里的这两项。单独的 `--settings` 设置进程也处理。已有的小肥鱼配置和会话（`config-slot-N.json`、`sessions-slot-N`）不动。改成 false 并重启桌宠即恢复 |
| `single_instance` | true | 桌宠已经在运行时又启动了一次（双击桌面图标、开始菜单等）：不再多开第二只（第二只有自己单独的会话列表，看起来像聊天记录不见了），而是把正在运行的这只的字符画窗口拿到最前面，关掉了就重新打开。带 `--slot` 等参数的启动照常多开（“生小肥鱼”已删去，见 `remove_spawn_pet`）。只有主实例（槽位 0）接收，按当前用户区分 |

| `chat_theme` | `ascii` | “AI 对话”经典窗口的皮肤：`line` 为 LINE 风格（v1.4.0），`ascii` 为字符画风格，`original` 为桌宠原样。字符画右键 → 字符画 →「对话框风格（AI 对话窗口）」里三选一，已打开的窗口立即生效，选择会被记住 |
| `chat_title` | `DeepSeek` | LINE / ASCII 皮肤下，对话框标题栏显示的文字 |
| `integrate_island` | true | 把原来的灵动岛收进字符画窗口右下角的「◈ 灵动岛」按钮（点击弹出卡片），屏幕上浮着的灵动岛隐藏；字符画右键 → 字符画 →「灵动岛收进窗口右下角的按钮」可以切换 |

| `custom_presets` | true | 允许主模型在对话中用 `new=` 自创表情，并在每轮消息末尾附上自创表情备忘 |
| `custom_presets_max` | 60 | 表情库上限；超出时淘汰最久没用、用得最少的 |
| `evolve` | true | 后台表情进化 |
| `evolve_min_replies` / `evolve_interval_min` / `evolve_daily_limit` | 6 / 30 / 6 | 上次进化后至少攒够几轮新对话（跨重启累计）、两次进化间隔多少分钟、每天最多几次 |

| `experiment_daily_limit` / `experiment_interval_min` / `experiment_idle_min` | 4 / 45 / 10 | 每天最多几次、两次至少隔多少分钟、至少多少分钟没有互动才开始 |

| `vision_enabled` | true | 后台视觉评价（只评价全新部件、骨架改造、自由演出）。没有支持看图的模型时自动只用本地检查 |

| `vision_daily_requests` / `vision_daily_tokens` | 12 / 40000 | 视觉评价每天的次数和 token 上限 |
| `vision_min_interval_s` / `vision_timeout_s` / `vision_max_pending` | 20 / 45 / 2 | 两次评价的最小间隔、超时、最多排队几个（同一时间只跑 1 个） |
| `sleep_tell_model` | true | 被对话吵醒时，在那条消息末尾附一句“你刚才睡着了，被这条消息吵醒”（只附在发给 API 的这一轮请求里，不写进会话记录和记忆），她可以带点刚醒的迷糊回话 |
| `evolve_thinking` | true | 进化时开启 DeepSeek 思考模式。它在后台运行，不占聊天时间 |

**API Key 的查找顺序**（代码里没有写死任何 Key）：

1. `config.json` 里的 `api_key`
2. 环境变量 `PET_ASCII_API_KEY` 或 `DEEPSEEK_API_KEY`
3. 桌宠本体已保存在 Windows 凭据中的 Key（沿用聊天设置）

都找不到时，自动切换到 Mock 模式。

**环境变量覆盖**：`PET_ASCII_MODEL`、`PET_ASCII_BASE_URL`、`PET_ASCII_PROVIDER=mock`、`PET_ASCII_HOME`（数据目录）。

**数据目录**下有：

- `state.json`：视觉状态与当日用量
- `anim_cache/`：所有生成过的动画，可在测试台回放
- `saved/`：手动另存的动画
- `custom_presets.json`：表情库。包括自创表情（规格、来源、适用情绪、使用次数、👍/👎、历史版本、最近一次使用时的那句回复）、已淘汰的表情、别名、内置表情的使用次数 / 评价 / 改良版，以及最近的评价记录。
  - **保存方式（v0.4.4）**：在后台线程合并写盘，不占字符画窗口的时间。
    - 新建、修改、评价等改动在 0.5 秒内写入；使用次数攒 10 秒写一次。
    - 每次只重新序列化变了的条目，并逐段写文件。
    - 文件不缩进，表情参数保留 3 位小数。
    - 退出时会把还没写的写完；如果桌宠被强制结束，最多丢最近 10 秒的使用次数。
- `dialogue.json`：表情进化用的最近对话素材（与桌宠记忆无关，测试台可清空）

  character.py   角色素材：姿势、面部区域、脸底、默认五官；内置小幽灵备用角色
  convert.py     视频帧 / 图片 → 彩色字符画角色（Pillow + ffmpeg）
  engine.py      本地动画引擎：关键帧轨道、补间、眨眼、呼吸、跳跃、视觉状态
  effects.py     本地特效（14 种）；background.py 字符背景（4 种）
  render.py      Qt 字符渲染器：逐格绘制，字形缓存，只重绘变化的格子
  window.py      透明桌宠窗口；lab.py 开发测试台

### 3.1 分层渲染（z 从低到高）

背景 → 身体（含脸底）→ 身体字符流纹理 → 身体补丁 → **面部** → 覆盖补丁 → 特效 → 全画布场景 → 界面（气泡）

上层的非透明格会完全替换下层同一格，因此一格只画一个字，不会出现字符叠影。

**面部区域的处理**：素材转换时自动检测脸部皮肤区域，生成两样东西：

- **脸底（plate）**：去掉五官、只剩皮肤，放在身体层里。
- **默认五官（neutral）**：原画的眼睛和嘴，作为默认的面部补丁。

AI 画的新五官盖在脸底上，透明的地方露出皮肤。所以头发、脸的轮廓永远由本地保持，不会被 AI 补丁破坏。

### 3.2 坐标与覆盖规则

- **坐标**：原点 (0,0) 在目标区域的左上角。x 是列，向右增大；y 是行，向下增大。一个字符占一个格子。
- **锚点**：`face`（面部区域左上角）、`body`（身体左上角）、`canvas`（画布左上角）。
- **越界**：越界的内容直接裁剪，不报错，也不会写到别的区域。
- **透明与清空**：
  - `` ` ``（反引号）永远表示透明，保留下层。
  - 空格默认也是透明；在帧里写 `"blank":"clear"` 时，空格表示主动清空成空白。
- **遮罩**：可选的 `mask` 行，`.` 表示该格保持不变，其它字符表示写入（此时空格表示清空）。
- **字符集**：AI 只能用单宽字符，即可打印 ASCII 加一组符号 `░▒▓█▀▄■□●○◆◇★☆♥♡♪♫✦✧·•°…※≈≡×←↑→↓∞`。中文等宽字符在补丁中会被替换成 `?`。本地的气泡可以显示中文（宽字符占两格）。
- **对齐**：每个字符单独画在自己的格子里，字体宽度不会造成错位。

### 3.3 三种生成模式（自动选择）

| 模式 | 什么时候用 | AI 输出 |
|---|---|---|
| Mode 1 参数 | 意图只涉及动作，例如「眨眼」「看向左边」「跳一下」 | `parameter_animation`，可加 `effect` |
| Mode 2 局部（默认） | 需要新的五官或局部形态 | `face_patch` / `delta_update` / `region_patch`，加参数和特效 |
| Mode 3 全画布 | 意图里有「乱码、解体、变成、崩坏、全屏…」 | `full_scene`（全画布关键帧或规则），加特效 |

- 对话联动和自主表达只允许 Mode 1 和 Mode 2。
- 如果模型越权输出了 Mode 3 的操作，这些操作会被剔除。

### 3.4 JSON 动画协议

```json
{
  "mode": 2,
  "intent": "害羞地低下头",
  "expression": "低头害羞，脸颊泛红",
  "think": "DON'T LOOK AT ME...",
  "priority": 6,
  "ops": [
    {"type": "parameter_animation", "duration_ms": 700, "params": {"gaze_y": 0.9, "head_tilt": -1, "bob": 0.5}},
    {"type": "face_patch", "palette": {"a": "#16205a", "b": "#3d7bff", "c": "#ffffff", "e": "#ff9fbf"},
     "frames": [
       {"rows": ["…面部区域宽 × 高的字符…"], "colors": ["…同尺寸的调色板字母…"], "ms": 300},
       {"delta": [{"x": 3, "y": 5, "text": "///", "colors": "eee"}], "ms": 400}
     ],
     "loop": "once", "hold": "last", "eyes": [[4, 2, 6, 3], [18, 2, 6, 3]]},
    {"type": "effect", "effect": "particles", "chars": "♥", "color": "#ff7fa8", "direction": "up", "duration_ms": 1500}
  ],
  "end_state": {"face": "hold"}
}
```

**操作类型**：

- `parameter_animation`：可控参数有
  - 视线与头部：`gaze_x/y`、`head_tilt`
  - 身体运动：`body_dx/dy`、`jump`、`bob`、`sway`、`shake`、`speed`
  - 眨眼：`blink`（once / twice / slow / rapid / closed / auto / none）
  - 外观：`tint` + `tint_amount`、`opacity`、`background`、`pose`
  - 补间曲线：`ease`
- `face_patch`：面部关键帧。
  - `loop` 可选 once / loop / pingpong，`repeat` 指定重复次数。
  - `hold` 为 last 时保留最后一帧，为 neutral 时恢复默认五官。
  - `eyes` 标出眼睛框，本地据此自动眨眼。
- `region_patch`：任意区域的关键帧，可以是手、呆毛、道具或文字。
  - 有 `anchor`（锚点）和 `layer`（body / overlay）。
  - `hold` 为 restore 时结束后恢复原样，为 last 时保留。
- `frame_sequence`：关键帧序列，按 `target` 规整成上面两种之一。
- `delta_update`：差分修改，只给出要改的坐标、字符和颜色。
- `full_scene`：全画布演出。
  - `hide` 指定要隐藏的层（body / face / background / effects）。
  - `then` 为 restore 时结束后恢复，为 hold 时保持。
  - 可以给 `frames`，也可以只给本地规则 `rules`。
- `effect`：本地特效。
  - 可用：particles、sparkle、symbols、glitch、dissolve、bubble、flash、fade、color_shift、shake、rain、ripple、text、scanline。
  - 参数：`chars`、`color`、`count`、`intensity`、`direction`、`text`、`anchor`、`duration_ms`。

所有操作都可以加 `delay_ms` 来编排先后顺序。

**帧**：

- 完整帧写 `rows`，可附 `colors`、`palette`、`color`、`mask`、`blank` 和 `ms`。
- 差分帧写 `delta`。
- 颜色用调色板字母表示；`.` 表示默认色（五官的深色）。

**限制**（超出时裁剪或丢弃，并记录警告）：

- 最多 10 个操作；每个操作最多 16 帧，总帧数最多 32。
- 每帧 40~6000 ms。
- 区域补丁最大 48×32。

**安全**：

- 协议里只有数据，没有任何可执行内容。
- 未知字段会被忽略。
- 输出解析失败时，带着错误信息让模型修正一次。仍然失败就回退到缓存或本地生成，渲染器不会崩溃。

### 3.5 Token 优化

- **关键帧**：模型一次输出 2~6 个关键帧，本地按时间播放，不需要逐帧请求。
- **局部更新**：默认只生成面部区域。头肩特写的面部区域约 32×11，全身约 24×8。
- **差分帧**：变化小的帧用 `delta` 只写改动的位置。
- **本地补间**：位移、跳跃、漂浮、色调、透明度和特效全部由本地计算。
- **前缀缓存**：系统提示词固定不变，因此能命中 DeepSeek 的前缀缓存。实测每次约 1792 / 2500 个输入 token 命中缓存。
- **动画缓存**：相似意图（且面部尺寸相同）的动画可以按概率直接复用。测试台里可以回放任何历史动画。
- **调度**：
  - 同义请求去重。
  - 新请求会取消已过时的旧请求，旧请求的结果直接丢弃。
  - 两次调用之间有最小间隔，并受每日预算限制。
  - 等待期间待机动画照常播放。

### 3.6 视觉状态与连续性

每次请求只发送压缩后的视觉状态（约 1~2 KB），不会附带历史帧。内容包括：

- 当前姿势、可用姿势；
- 面部区域尺寸和皮肤色；
- **当前的脸**（字符行 + 调色板字母）；
- 当前表情和最近 5 个表情；
- 正在播放的动画、非默认参数和背景。

模型据此在现有的脸上继续变化，例如只让嘴微张。重启后会恢复上次的脸、姿势、表情记忆、背景和当日用量。

### 3.7 自主表达

默认关闭，可在测试台或右键菜单中打开。打开后，空闲时每 4~12 分钟（可配置）从一组小意图中挑一个交给模型，例如「偷偷观察一下用户在忙什么」，或「即兴在身边用字符画一个小图案」。是否表现、如何表现由模型决定。

- 受每日次数和 token 预算限制。
- 普通的待机动画（眨眼、东张西望、呼吸漂浮、背景滚动、字符流）完全离线运行，不调用 API。

### 3.8 面部骨架与内联表情（v0.2）

**为什么改**：v0.1 让模型直接写一块 32×11 的字符矩阵当作脸。

- 大模型很难数准列，瞳孔会画到错误的位置。
- 面部区域是靠“肤色检测”找的，而动漫的大眼睛是深色，检测出的区域其实只是脸颊。
- 墨色被统一提亮成中蓝，黑眼珠与头发混在一起。
- 嘴、腮红被“调色板字母修正”画成了实心色条。

**现在的做法**（`face_rig.py`）：

1. 标定文件 `assets/source/maid_rig.json` 记录原图像素坐标：眼睛中心、尺寸、虹膜、眉毛、嘴、脸颊、汗滴位置，以及原画配色。
2. 每次渲染时，在“无五官”原图的脸部区域上，按参数在像素级绘制五官，风格与原画一致：
   - 粗黑上眼线、白色眼白、黑+蓝渐变虹膜、星形高光；
   - 笑眼 ^、闭眼、生气或难过的斜眼睑、心形 / 星形 / 漩涡 / 点状瞳孔、> < 眼；
   - 泪、汗、脸红排线、额头黑线；
   - 普通 / 张口 / 露齿 / 吐舌 / 波浪 / 猫嘴 / 嘟嘴 / O 型 / 三角嘴。
3. 绘制结果用与身体**完全相同**的裁剪网格、亮度梯度和配色转成字符，只替换面部区域。
4. 参数为默认值时，该部位直接用有五官版原画的像素。所以默认表情就是原画；眨眼、看向别处时才切换为绘制版。
5. 场景图的字符化保留墨色：最暗处是稀疏字符和暗色，黑眼珠、眼线才能与中间调的头发区分开。

**表情规格**（每个字段都可选，没写的沿用上一帧）：

```json
{"preset": "shy", "level": 0.8,
 "eyes": {"open": 0.75, "smile": 0.3, "tilt": 0, "iris": 1, "pupil": "art", "tear": 0, "highlight": 1},
 "eye_l": {}, "eye_r": {"smile": 1.0},
 "gaze": [-0.6, 0.5],
 "brows": {"y": 0, "angle": -0.5},
 "mouth": {"shape": "wavy", "open": 0, "width": 0.7, "curve": 0},
 "blush": 1.0, "sweat": 0, "gloom": 0}
```

- **预设（30 个）**：neutral calm smile happy laugh grin shy embarrassed sad cry teary angry pout surprised shocked confused sleepy bored smug wink love starstruck dizzy determined thinking worried scared dead closed cat。
- **查看效果**：`python tools/face_gallery.py maid_bust 输出.png [预设...]` 渲染表情图鉴；测试台“本地表情预设”下拉框可即时切换。

**协议新增 `face` 操作**：`{"type":"face","frames":[{表情规格..., "ms":停留毫秒}],"blend_ms":过渡,"loop":"once|loop|pingpong","hold":"last|neutral"}`。

- 帧与帧之间由本地引擎做参数插值，每一步都由骨架重新绘制，过渡平滑。
- 发给模型的视觉状态只剩约 0.5 KB，内容是当前表情与默认值的差异。

**内联表情标签**（`inline.py`）：

- 格式：`<face 预设 level= blush= look=left|right|up|down|away act=nod|shake|jump|bounce|sway|lean|shiver fx=hearts|sparkle|question|exclaim|anger|tears|notes|zzz|glitch|flowers|sweat|gloom then=预设>`。
- 剥离：`TagFilter` 在流中剥离标签，即使标签被拆在多个数据块里也能正确处理。
- **为什么还要每轮提醒（v0.4.2）**：真实对话里模型常常不写标签。排查结论如下：
  - 系统提示里的表情说明确实在，“说明没加上”的可能可以排除；
  - 但请求里带着她以前的 17 条回复，会话记录里存的都是剥掉标签后的文字，模型照着历史的样子省略了标签；
  - 测试探针没有历史，所以每次都带标签。
  
  修复：在本轮用户消息末尾附一句格式提醒（`integration.prepare_inline_messages`）。提醒放在最后，系统提示和历史都不动，前缀缓存照常命中。
  
  试过但没有采用：把猜出来的标签补回历史回复里。标签率同样是 8/8，但模型会照抄那种简化标签（`<face X idle=keep>`），不再写动作、特效和挂机时间，表情变得单调。
- 在桌宠里的接入点：
  - 系统提示末尾追加固定的表情说明（`PromptBuilder.build_messages` 外层）；
  - 剥离标签并驱动说话口型（`OpenAICompatibleProvider.stream` 外层）；
  - 没有标签时本地兜底（回复完成回调）。

### 3.9 自创表情（v0.3，`custom_presets.py`、`ai/evolve.py`）

DeepSeek 可以按自己想表达的情绪创造新的表情预设，有两条途径。

**A. 对话中即兴创造（主模型，不额外请求）**

- 现有表情都不贴切时，主模型在回复开头的标签里写：
  `<face new=气笑 from=smile smile=0.5 brow=0.4 browy=-0.2 mouth=wavy mwidth=0.8 curve=0.3 blush=0.3 sweat=0.4 look=away>`
- 参数是扁平写法，不用写 JSON：`open smile tilt iris pupil tear highlight`（可加 `l.` / `r.` 前缀只改一只眼）、`brow browy mouth mopen mwidth curve blush sweat gloom look`。`from=` 指定从哪个预设出发。
- 本地会把参数钳制到合法范围后，规整成完整的表情规格存入表情库，并立即演出。之后模型直接写 `<face 气笑>` 就能复用。
- 模型怎么知道自己创造过什么：每轮发送前，在**最后一条用户消息末尾**附一行备忘，列出最近用过的自创表情名，例如 `〔表情备忘：你自创过的表情有 气笑、傲娇…〕`。系统提示保持不变，所以前缀缓存照常命中；备忘也只出现在发给 API 的请求里，不写入会话记录和记忆。
- 去重：新表情和任何已有表情（内置或自创）参数几乎一样时（差异 < 0.35），不新增，直接沿用已有的名字。名字不能和内置预设重名，不能超过 12 个字。
- 生成器（`ai` 联动和测试台生成）的 JSON 输出也可以带 `new_presets`，规则相同。

**B. 后台表情进化：自我迭代的闭环（v0.4）**

创造 → 使用 → 反馈 → 修改 / 合并 / 淘汰，每一步都有记录：

1. **对话素材**：最近 16 轮对话（用户说的话、她的回复、当时的表情标签）存在字符画数据目录的 `dialogue.json`。
   - 重启不丢，新增轮数跨重启累计。
   - 与桌宠的聊天记录、永久记忆完全分开，**不读取也不修改记忆**。
   - 自检探针不计入。
   - 测试台可一键清空。
2. **使用次数**：每次对话标签、挂机切换用到的表情，不论内置还是自创，都会计数，并记下最近一次使用的时间。
3. **你的评价**：在桌宠窗口右键选「👍 喜欢现在这个表情」或「👎 不喜欢」。测试台里也可以选中某个表情来评价。
   - 评价连同当时她说的那句话一起记下，作为进化时最重要的依据。
   - 点完后她会有个小反应，标题栏显示“记下了”。
4. **照镜子**（`face_rig.mirror_text`、`FaceRig.visible_diff`）：DeepSeek 看不了图，所以把每个表情实际画出来的样子翻译成文字，例如“双眼弯成 ^ 形的笑眼；闭着的嘴，嘴角上扬；额头挂着汗滴”。
   - 再算出它最像哪个已有表情，以及两者渲染成字符画后有多少格不同。
   - 低于 5% 就是肉眼几乎分不出来。
   - 照镜子还会提醒她：眉毛画在深色刘海上几乎看不见。
5. **设计**：条件满足时，后台请副模型（`config.json` 的 `model`，默认 deepseek-flash，开启思考）以“表情设计师”身份回顾以上全部信息，输出 0~4 个动作：
   - `create`：新建；
   - `revise`：修改，只写要改的字段；
   - `merge`：把太像的两个合并，旧名字变成别名，照样能用；
   - `retire`：淘汰，进入“已淘汰”，可恢复。
   
   自动进化的条件：上次进化后至少 6 轮新对话、距上次至少 30 分钟、今天未满 6 次。
6. **照镜子复查**：新建或修改过的表情再照一次镜子交还给她。不到位就再修一次。这一步不开思考，比较便宜。
7. **变化幅度（v0.4.1）**：以前她的修改太保守，在字符画上只改变了 5~8% 的格子，肉眼很难看出来。现在：
   - 每次修改和她自己的上一版比，新建和最像的已有表情比，目标是 `evolve_min_change`（默认 10%）；
   - 不够就沿着她改的方向自动放大（外推参数），最多 3 倍；
   - 放大后达到目标的 75% 就采用；
   - 仍然太小的修改不采用，在照镜子复查时退回给她，要求改得更大胆；
   - 新建的表情放大后仍几乎看不出区别（低于目标的 1/3）时，并入最像的表情；
   - 对话中用 `new=` 即兴创造的表情也走同样的放大。
   
   提示词里也告诉了她实测的规律：字符画上最显眼的是眼睛（睁闭、^ 笑眼、眼角斜度、瞳孔、左右不对称）和视线；嘴的张合、泪、汗、脸红、黑线各自只改变约 1% 的格子，只能当点缀。
   
   `FaceRig.visible_diff` 不计“暗对暗”的格子，比如深色刘海上的眉毛。
8. **输出解析失败时（2026-10-16 修复）**：真实运行中出现过一次“输出中没有可解析的 JSON 对象”。设计请求开着思考，思考的 token 也算在 `max_tokens` 里，原来的上限 4000 很可能被思考用完、正文为空（当时没记 `finish_reason`，事后无法确认）。现在：
   - 上限提高到 8000（只是封顶，按实际用量计费）；客户端返回 `finish_reason`；
   - 解析失败时日志记下 `finish_reason`、token 用量（含思考）和原文片段（≤200 字，取头尾）；
   - 再**不开思考**补问一次“只输出一个 JSON 对象”：原输出为空时把要求接在原来的用户消息后面，被截断时附上截断的部分；
   - 被截断的输出里如果只剩一个完整的动作（或照镜子复查只剩一条），以前会被当成“没有改动”悄悄跳过，现在算解析失败；
   - 补问后仍失败：日志写明两次的原因（`表情进化失败（…s，… token）…；补问后仍失败：…`），花掉的 token 照样计入预算，对话素材不清零，过了间隔还会再试。

**护栏**（写在代码里，不靠模型自觉）：
- 👍 多于 👎 的表情不会被淘汰或并掉；
- 内置表情只能 revise，且只有 👎 多于 👍 时才能改，改过的叫“改良内置”，随时可恢复原版；
- 每次修改都保留版本（最多 8 个），可以回滚；
- 一次最多 4 个动作、最多新建 3 个。

**表情库管理**：测试台「自创表情」页可以完成以下操作：
- 列出在用的自创表情、改良过的内置表情和已淘汰的表情；
- 每项显示使用次数、👍/👎、第几版，鼠标悬停可以看到照镜子描述；
- 预览、评价、回滚上一版、恢复（已淘汰 / 内置原版）、重命名、删除、立即进化、清空对话素材。

桌宠窗口右键「切换表情」里也能找到全部自创表情（列表可以用滚轮滑动）。

### 3.10 说完之后：决定是否、何时进入挂机（v0.3）

主模型在开头标签里必须写上 `idle=` 和 `after=`，决定这句话说完之后做什么：

```
<face 犯困 level=0.4 droop=0.5 mouth=wavy mopen=0.3 idle=calm after=60>（实测：说完 2 分钟后换成 calm 进入挂机）
```

- **至少 1 分钟后才挂机（v0.8.1）**：以前回复一说完，最快 0 秒就进入挂机，用户还在看回复时她就换了表情。
  - 现在，回复结束后先保持当前表情 `idle_min_delay_s`（默认 60）秒，再加上她自己决定的 `after` 秒，才进入挂机。
  - “要不要换、换成什么、1 分钟后再等多久”仍由她自己决定。
- `idle=表情`：挂机时换成的表情，可以是内置或自创表情。
- `after=秒`：1 分钟之后再等多少秒，范围 0~240，超出会被截断；没写时默认 30 秒。旧习惯写的小数字（例如 3）就是 1 分 3 秒。
- `idle=keep`：保持当前表情；同样要等到 1 分钟 + `after` 之后才算进入挂机。
- 正文写完后如果改了主意，可以在末尾再加一个收尾标签覆盖，比如 `<face idle=calm after=20 look=down fx=zzz>`。它同样会被剥离，前面的空行也会一并去掉；其中的 `look/act/fx` 在切换时一起演出。
- 计时从回复**完全结束**（流式输出完成）时开始。到点后用 0.7 秒慢慢过渡到挂机表情，标题栏显示“· 困倦 · 挂机中”。计时期间，只在最后 10 秒显示“即将挂机”，免得一整分钟都挂着这几个字。
- 用户发来新消息、新一轮回复开始，或者手动切换表情（右键菜单、测试台）时，没执行的切换会被取消，桌宠也会退出挂机。标题栏和 👍/👎 都以最近一次切换的表情为准（v0.4.3）。
- 只在 `chat_link: inline` 下生效。测试台「状态」页会显示最近一次决定，以及切换的执行或取消情况。

### 3.11 窗口样式（v0.3）

- 默认 `window_style: "framed"`：深色不透明面板，带圆角、柔和阴影和标题栏。背后的桌面不会再透过画面。
- 标题栏从左到右是：
  - 状态灯（绿 = 就绪，黄 = 生成中或表情进化中，灰 = Mock）；
  - 角色名 · 当前表情（自创表情也显示名字）；
  - 按钮：≡ 打开测试台，◆/◇ 置顶开关，— 最小化到任务栏（v0.6.1 起；以前是“收起”），× 关闭。
- 右键菜单「透明悬浮样式」可以切回旧样式。选择会保存，下次打开窗口时生效。
- **任务栏里的窗口（v0.6.1）**：以前它是“工具窗口”，任务栏和 Alt+Tab 里都没有它。点了 — 以后画面收成一条标题栏，被别的窗口挡住就找不到了（实际发生过：找不到窗口，于是又开了一个桌宠）。现在：
  - 它是普通的顶层窗口：任务栏里有图标，Alt+Tab 里也有，外观不变（仍然无边框、圆角、可置顶）；
  - 标题栏的 — 是真正的最小化，点任务栏图标就恢复，窗口在原来的位置；再点一下任务栏图标又会最小化；
  - 托盘的「显示 / 隐藏」、灵动岛的「显示桌宠」也会把最小化的窗口恢复并提到最前；
  - 任务栏图标是她现在的脸：从当前画面裁出脸部做成圆角方形图标，表情或睡眠状态变了就跟着换（每 3 秒看一次），睡着时是闭眼的睡脸；
  - 原来的“收起”（只留标题栏）改成双击标题栏，或右键「字符画 → 收起画面 / 展开画面」。
- **右边的黑边（v1.3.9 修好）**：以前窗口右边偶尔会多出一条黑边。原因是标题栏的状态文字——睡着时的梦话（「主人……不要走……」）、在房间里时的房间状态——太长时会把窗口撑宽（标题栏最小宽度一度到 690px），之后文字变短了窗口也不会缩回来，字符画还是原来的宽度，多出来的部分就是黑边（实际出现过 565×540，正常应为 472×540）。现在：
  - 状态文字不再决定窗口宽度，放不下就用“…”省略，鼠标悬停在标题栏上能看到全文；
  - 保底：窗口比内容大（不管什么原因，例如显示器缩放变化）时，每 3 秒检查一次，自动缩回内容大小。

### 3.12 “AI 对话”窗口的皮肤：ASCII（v0.5.1，`chat_theme.py`）与 LINE（v1.4.0，`chat_line.py`）

桌宠的经典聊天窗口（`chat_ui_style = classic`）在运行时换上和字符画一致的风格，不改动桌宠的任何文件：

- **整体**：深色终端面板（与字符画窗口同色 `#0b0e14`），小圆角。标题、按钮、状态、提示等标签用等宽字体（Cascadia Mono / Consolas），标题栏下方是虚线分隔。
- **标题（v0.5.2）**：标题栏显示“DeepSeek”（`chat_title`，原来是“角色名 · AI 对话”），头像字母跟着变成“D”。关掉皮肤时还原原来的标题。
- **消息**：每条消息用制表符画边框，名字写在上边框里，原来的圆形头像去掉。她的消息粉色，在左，形如 `┌─[ DeepSeek娘 ]────┐`；你的消息青色，在右，形如 `┌────[ ME ]─┐`。生成中的回复边框变成琥珀色，末尾有块状光标 `▌`；出错是红色，停止是灰色。
- **背景**：消息区铺一层极淡的字符纹理（`. : · ' -` 等，亮度差约 5%）。
- **可读性**：
  - 正文仍用微软雅黑，并从 11px 放大到 13px；输入框也是 13px。
  - 去掉头像后，气泡最宽从 72% 提到 80%；长消息会撑满可用宽度，每行从约 14 个字增加到约 19 个字。
  - 对比度全部达到 WCAG AA（≥ 4.5:1）：正文 14.9:1 和 14.7:1，次要文字 ≥ 5.3:1，边框和名字 8.2 ~ 9.9:1，输入框 16.3:1。
- **不套用皮肤的情况**：
  - 在桌宠设置里给聊天窗口设置了背景图片时，保持原样。
  - 现代聊天窗口（`chat_ui_style = modern`）不受影响。
- **实现**：包装经典窗口的 `_style`（换样式表）、`_update_bubble_widths`（加宽气泡，并在消息区尺寸变化时重算），以及消息气泡的 `__init__` / `set_content` / `set_state` / `paintEvent`（隐藏头像、生成中光标、画边框）。消息区的容器没有对象名，样式表管不到，所以直接设调色板。

#### LINE 风格（v1.4.0，`chat_line.py`）

仿照 LINE 手机版的聊天界面（配色参考其截图取色）。这只是界面风格上的模仿，与 LINE / LY Corporation 无关，没有使用其任何图标、图片或素材。和 ASCII 皮肤一样只在运行时套用，不改桌宠的文件；三种风格可以随时互相切换，切回去时布局、头像、输入框都原样还原。

- **背景**：整个窗口是淡蓝的天空（`#8BABD7` → `#9DB8E0`），带几朵极淡的云；标题栏透明，只留粗体的“DeepSeek”（方形头像字母和副标题“陪伴式对话空间”隐藏）。会话栏是一条半透明的白色磨砂条，按钮是白色圆角。
- **她的消息**：左边是圆形头像，白色圆角气泡，左上角有一个朝头像的小尾巴。头像是她的“开心”表情：用面部骨架的手绘差分画成一张普通的图（变成字符画之前的样子），裁成圆形；第一次用时渲染一次，存成数据目录里的 `chat_avatar_<角色>.png`（删掉就会重新画）。没有面部骨架的角色改用字符画笑脸，再不行就是粉色圆形“D”。
- **你的消息**：右边，绿色气泡（`#6CE67B`），尾巴在右上角，不显示自己的头像，也不显示名字（1 对 1 的 LINE 就是这样）。
- **分组**：同一个人在同一分钟里连着发的几条，只有第一条带头像和尾巴，后面几条留出头像的位置对齐。
- **时间和既読**：每条消息外侧底部是发送时间（HH:MM，会话里存的 UTC 时间换成本地时间；鼠标悬停在气泡上看完整日期）。你的消息后面只要有她的气泡（她开始回了），旁边就显示「既読」，和参考图一样用日文。
- **她在想的时候**：回复还是空的，气泡里显示 “• • •”，不显示原来那行“正在生成…”。
- **输入栏**：白底，一行：左边圆角的 “Aa” 输入框，右边绿色的「发送」。输入框随内容长高，一行起、最多 5 行，再多就在框里滚动（一行时不会出滚动条）。原来的“内容会保存到当前角色的本地会话”提示隐藏。
- **可读性**：正文 14px，`#111` 在白 / 绿气泡上 18.9:1 / 11.9:1；时间、既読 `#2B3B57` 在天空上 4.8:1（顶部）~ 5.6:1（底部），云只会让底色更亮；「发送」深绿字在绿底上 ≥ 9:1。短消息按一行的宽度，不会像原来那样无故折行；长消息撑满可用宽度，不出横向滚动条。
- **实现**：`chat_theme.py` 多包装了窗口的 `_add`（新气泡套样式、记时间、重新分组）、`_load`（把会话里每条消息的 `created_at` 对到气泡上）、`_remove_bubble`（重新分组）。气泡本身透明，圆角、尾巴、时间和既読都在气泡的 `paintEvent` 里画；天空画在外壳 `phone-shell` 上（事件过滤器），消息区设为透明透出来。输入框是从原来的竖排布局里挪进按钮那一行的，切回去时再挪回原位。
- **实测**：在作者自己的桌宠里用自检打开真实的“AI 对话”窗口（只读），全部消息都换成了 LINE 样式、都对上了时间，输入框在一行里，没有横向滚动条；自检截图里有真实对话，没有查看就删掉了，外观是用临时数据目录里虚构的对话截图检查的。记忆库指纹前后一致。

### 3.13 灵动岛收进窗口右下角的按钮（v0.5.4，`island_bar.py`）

原来浮在屏幕边上的灵动岛，被收进字符画动画右下角的「◈ 灵动岛」按钮（只有框式窗口才有）。平时只显示按钮；鼠标移上去变粉，点击后在按钮上方弹出卡片：

```
┌───────────────────────────────────────────────────────────────────────┐
│ 余额 ¥12.34   刚刚              DeepSeek 当前空闲 · 下一高峰 09:00   [⟳] │
│ [显示桌宠] [设置]  › 最近一条消息……                                     │
└───────────────────────────────────────────────────────────────────────┘
[>_ 对话]                                                       [◈ 灵动岛]
```

- **展开 / 收起**：点按钮弹出，点卡片以外的地方或再点一下按钮就收起。窗口本身不变高。
- **余额**：点开卡片时会查一次。后台也在保持更新，所以一点开就是较新的数字。
  - 后台查询的时机：启动后、每隔 `island_balance_refresh_min` 分钟、每次对话回复后 3 秒；卡片里的 ⟳ 也可以立即查。
  - 括号里的充值 / 赠送明细放在悬停提示里；余额后面的小字是“多久前查的”。
  - “查询中… / 刚刚查询过，稍后自动更新 / 查询失败”这类状态不会盖掉已经查到的余额，只显示成小字。
- **峰谷时段**：空闲时青色，高峰时琥珀色，每半分钟刷新。
- **卡片里的按钮**：
  - 「显示 / 隐藏桌宠」：同右键菜单里的开关，选择会记住。
  - 「设置」：打开灵动岛设置。
  
  AI 对话的入口是左下角的「>_ 对话」，卡片里不再重复。
- **有新事件时**（余额更新、峰谷切换、新消息），「◈ 灵动岛」按钮会短暂变粉，提示可以点开看看。
- **数据来源**：仍是桌宠自己的灵动岛逻辑，包括余额查询、缓存、限频、没配 API Key 的提示、峰谷文字、最近消息。灵动岛对象照常存在，只是隐藏，它的 `set_balance_info` / `set_last_message` / `notify_event` / `set_pet_visible` 被转发到卡片。
- **屏幕上的灵动岛保持隐藏**：同时拦截它的 `show()` 和 `setVisible()`，所以桌宠在设置变化后重新显示它也不会冒出来。
- **什么时候会放回屏幕上**：关闭字符画窗口时，或在菜单里关掉「灵动岛收进窗口右下角的按钮」时。
- **灵动岛点一下就出聊天的“隐藏聊天”入口不再可用**：它依附在屏幕上那个灵动岛旁边。需要聊天时用「>_ 对话」。
- **历史**：v0.5.3 时是一条常驻的底栏，v0.5.4 按要求改成平时收起、点击才弹出。

### 3.14 睡眠模式（v0.6，`sleep.py`）

超过 `sleep_after_min`（默认 30）分钟没有互动，她会睡着；在对话里给她发消息就会被吵醒。睡眠和吵醒的动画全部是本地预设，不调用 API、不花钱。

**入睡（3 种过程，随机，不会连续两次一样）**：

- 打哈欠：眼皮变沉 → 张大嘴打哈欠、眯眼带泪，冒出“哈啊——” → 眼睛闭上又勉强睁开几次 → 睡着；
- 点头：眼皮越来越沉、头往下掉 → 猛地惊醒（“!”和一下抖动）→ 又慢慢闭上；
- 晚安：微笑着说“晚安……”，揉揉眼睛（左右眼轮流眨），打个小哈欠，带着笑睡着。

入睡的同时，画面慢慢“入夜”：整体压暗、偏蓝，随呼吸极轻地明暗起伏；Z、鼻涕泡、梦话气泡这些特效不受夜色影响，仍然是亮的。身上字符流里的文字换成梦话，比如 `<DREAM> counting_clouds(38)... 39...`。

**睡着之后：即时编排，不是循环素材**。睡眠控制器每次只排下一“拍”（1~3 口呼吸，约 4~15 秒），每拍都重新随机：

- **呼吸**：每口呼吸 3.3~5.2 秒，睡得越久越慢。吸气时嘴微张、脸微红、画面微亮；呼气时冒出一串 z → Z → 大 Z（字母拼成的字符画 Z，一个比一个大，沿右上方排开再飘走）。每口呼吸的时长、冒几个 Z 都不同；
- **梦境情绪**：安稳、打鼾（嘴随呼吸一张一合）、梦里笑（闭着的眼睛弯成 ^ ^）、皱眉（额头阴影线、嘟嘴）、说梦话、流口水。每种持续 2~6 拍，切换时用 1.5~2.4 秒慢慢过渡；
- **随机小事件**，各有概率和冷却时间，所以不会规律出现：
  - 眼皮跳一下（微微睁开一条缝又合上）；
  - 深深叹一口气（这口呼吸更长，呼出一个大 Z）；
  - 梦话气泡，例如“唔……布丁……”“主人……再五分钟……”，共 12 句，不会连着重复；标题栏同时显示这句梦话（字符画里的中文只有一格高，标题栏里看得清）；
  - 鼻涕泡：随吸气一点点鼓起、呼气稍微缩小，吹到最大“啵”地破掉，溅出几个点；
  - 梦里笑时冒出小星星，流口水时嘴角滴下口水；
  - 身上的梦话文字隔一阵换一句。

**吵醒（6 种反应，随机，不会连续两次一样）**：

| 反应 | 过程 | 醒来后停在 |
|---|---|---|
| 吓一跳 | 闪白 + 抖动，眼睛瞪圆、瞳孔缩成点、冒“!” → 脸一下红透 → 不好意思地笑 | 微笑 |
| 迷迷糊糊 | 半睁眼 → 又闭上 → 揉眼睛打哈欠、冒“?” | 困倦 |
| 起床气 | 一只眼睁一条缝，阴着脸冒“#” → 嘟嘴 | 鼓脸 |
| 流口水被发现 | 口水滴下来 → 猛地睁眼“!!” → 脸红透、冒汗、眼睛往旁边躲 | 害羞 |
| 死机重启 | 画面乱码 + 抖动，瞳孔变成蚊香 → 困惑“?” → 恢复微笑 | 微笑 |
| 伸懒腰 | 眯眼张大嘴伸懒腰，冒小星星 → 猫嘴笑 | 开心 |

所有动画的节奏都带 ±12% 的随机抖动，同一种反应每次也略有不同。吵醒时夜色在 0.3~1 秒内褪去，梦话文字换回原来的思考文字。

**怎样算互动、怎样会吵醒**：

| 操作 | 醒着时 | 睡着时 |
|---|---|---|
| 在对话里发消息 | 推迟入睡 | **吵醒**（6 种里随机）；回复开头的表情标签、说完之后的挂机决定，都等吵醒动画播完再演 |
| 双击画面 | 戳她一下（一次表达） | 戳醒（吓一跳 / 迷迷糊糊 / 起床气 / 死机重启里随机） |
| 右键「字符画 → 叫醒她」 | — | 戳醒 |
| 输入表达意图（右键「说点什么」） | 照常 | 戳醒，醒来后再演你输入的意图 |
| 切换表情、恢复默认表情 | 照常 | 直接醒，不播吵醒动画 |
| 拖动窗口、Ctrl+滚轮、打开右键菜单 | 推迟入睡 | 不会吵醒 |
| 右键「字符画 → 现在睡觉」 | 立即入睡 | — |

**睡着时不做的事**：不做自主表达、不进入挂机、说话信号不会让她张嘴；如果睡着时恰好有 API 生成结果回来，也不会盖掉睡脸。睡脸不出现在 👍/👎 里（它不是可以进化的表情）。

**告诉模型她刚睡醒**（`sleep_tell_model`）：被对话吵醒的那一轮，发给 API 的用户消息末尾会多一句“〔你刚才睡着了（很久没人理你），被这条消息吵醒——可以带一点刚醒的迷糊或小起床气，但照常回答〕”。只附这一轮，不写进会话记录和记忆。

**关机、强制退出**：睡着时，每秒保存的视觉状态存的是“醒着的样子”（睁眼、原来的思考文字），所以直接关机或结束进程后，下次启动是醒着的。

**实现要点**：

- 状态：醒着 → 犯困（入睡过程）→ 睡着（睡眠循环）→ 被吵醒（吵醒动画）→ 醒着。
- 是否该入睡用真实时间（每 15 秒检查一次；正在生成动画、即将挂机时不入睡）；动画用引擎时间。
- 每段动画都排成标准 JSON 协议（`face` 关键帧 + `effect`），过一遍协议校验后交给引擎。一口呼吸是一个两帧的 `face` 操作（吸气慢慢过渡过去，呼气过渡完稍停一下）；一拍控制在 10 个操作、20 秒延迟以内。
- Z、鼻涕泡、夜色是三个新的本地特效（`SleepZ`、`NoseBubble`、`NightMood`），由睡眠控制器直接加到引擎里，跟着呼吸回调变化；它们的位置按骨架标定图上的额头、鼻尖、嘴角换算到字符格。
- 对话请求可能在工作线程里组装，吵醒动画通过信号回到界面线程再播。

### 3.15 自主创作（v0.7，`parts.py`、`visual_check.py`、`creative.py`、`ai/experiment.py`、`ai/vision.py`、`metrics.py`）

目标：让 DeepSeek 不只会**用**表情，还会**发明**表情、看到真实的呈现效果、自己改进，逐渐形成自己的视觉风格。类 Live2D 的骨架照旧保留，作为稳定的默认形态。

**现状分析（改动前）**

已经具备：
- 像素级的骨架渲染；
- 协议校验；
- 全画布自由演出（Mode 3 / `full_scene`）；
- 带版本、使用次数和 👍/👎 的表情库；
- 后台表情进化。

结构上的限制：
- 五官全是写死的 Python 绘制代码，模型只能调参数：10 种嘴型、7 种瞳孔、睁闭和斜度；
- 五官位置固定在标定点上；
- “照镜子”只是把参数翻译成文字，外加一个变化格数，不是对画面的检查；
- 没有越界、遮挡检查，没有视觉输入，不记录创作意图和失败原因，也没有防止收敛的机制。

**1. 可创造的组件**

组件是一段绘图数据：椭圆、折线、多边形、弧、矩形、星、心、圆点，加上可选的字符纹理（直接叠在字符画上的 `> <`、`TT` 这类字符）。
- 坐标在节点自己的框里；左右成对的部位自动镜像。
- 颜色用原画调色板里的角色名，或 #rrggbb。
- 每个组件都要经过校验和钳制：图元数、点数、坐标、线宽都有上限，名字有格式要求，不认识的字段直接丢掉。**模型生成的任何内容都不会被当作代码执行。**
- 组件按原画笔触在像素层绘制，再走同样的字符化流程，所以风格一致。
- 眼睛组件眨眼时会换成内置的闭眼弧线；嘴巴组件说话时整体上下张合。
- 组件库在 `components.json`：可以登记、复用、修改（保留版本、可以回滚）、淘汰、恢复，也记录使用次数、👍/👎 和视觉评价。

**2. 可编辑骨架**

默认骨架由原画标定推出：两眼、两眉、嘴、两腮、额头、汗滴，以及只作锚点的鼻、下巴、脸框。

表情规格可以带三组可选字段：
- `parts`：某个节点换成组件、隐藏，或恢复内置；
- `nodes`：移动（按脸框比例）、缩放、旋转节点；
- `extra`：新增最多 8 个节点（第三只眼、触角、面纹……）。

实验里模型也可以写骨架操作，按顺序执行：`move` / `scale` / `rotate` / `replace` / `add` / `remove` / `group`（一组节点一起平移、缩放、旋转）/ `reset`。
- 所有结果都会被钳制在约束内。
- 改造后的骨架可以存成“骨架方案”，在表情规格里用 `skeleton=名字` 引用。
- 没有这些字段的表情和以前完全一样：走原来的绘制路径，渲染结果、缓存键都不变（有测试保证）。

**3. 本地视觉检查（确定性，几十毫秒）**

每个候选都分层渲染一次，然后对**实际渲染结果**做检查：
- 部件画到脸部区域外；
- 部件大面积画在头发上（按无五官原图的肤色区域判断）；
- 部件互相重叠，比如眼睛压住嘴；
- 两眼左右颠倒，或眼睛跑到嘴下面；
- 嘴不在下半张脸；
- 每个部件在字符画上实际改变了几格，太碎就看不见；
- 和皮肤的颜色对比；
- 引用了不存在的组件，或组件什么也没画出来。

另外会按改动的部位自动确定截图范围，生成局部特写和整张脸缩略图（字符画和像素两种，用 PIL 绘制，后台线程可用）。
- 30 个内置表情全部检查通过，平均 23 ms。
- 确定性错误由本地解决：有错误时不调用视觉模型，也不允许采用。

**4. 自主视觉实验（后台）**

流程：

```
目标（风格 × 类型，探索 / 利用）→ 她提出设计意图和候选（组件 / 骨架操作 / 表情规格 / 自由演出）
→ 校验、钳制 → 本地真实渲染 + 确定性检查 → （高风险变化）后台视觉评价
→ 她看到实际结果后决定：修改 / 采用 / 放弃 → 最多 3 轮；最后一轮只能采用或放弃
```

- 类型有四种：发明新部件、改造骨架、重做旧作、自由演出。
  - “重做旧作”会把最近 6 个部件和 4 个自创表情的规格交给她挑。v0.7.1 修好了一个错误：以前这里取规格时报 KeyError 'spec'，所以每次抽到重做旧作都直接失败，0 轮、不花 token。
- 只在没人理她 10 分钟以上，或睡着时才做（睡着时字符流显示 `<DREAM> experiment.start(...)`）。
- 限制：每天最多 4 次，间隔 ≥45 分钟，每天 ≤60000 token，还受全局预算约束。可以随时取消。
- 采用后的去向：
  - 组件进组件库；
  - 表情进表情库，并带风格标签；
  - 骨架改造另存骨架方案；
  - 演出进演出库。

  醒着的话，她会顺便把新表情摆给你看。

**5. 异步双通道（视觉评价不拖慢任何东西）**

- 快通道（平时）：表情生成只经过本地快速结构验证，立即播放。眨眼、视线、参数微调、复用已验证的动画，都不会调用视觉 API。
- 慢通道（后台）：只有全新组件、骨架改造、自由演出这类高风险变化，才把截图交给看图模型。
  - 截图范围按实际改动的区域决定，同时给局部特写和整体缩略图。
  - 自由演出用专门的提示词说明“这不是一张脸”。实测中，用脸的提示词会让评审硬从抽象的星点里看出一张脸来。
- 约束：
  - 同一时间最多 1 个请求，最多排队 2 个；
  - 两次至少间隔 20 秒，超时 45 秒；
  - 每天 12 次、40000 token；
  - 任务可以取消；
  - 服务商不支持看图时，当天自动回退到只用本地检查。
- 评价结果异步写进创作记忆和组件记录，以后生成时供她参考。实验最多等 60 秒，没回来就先按本地检查继续。
- 视觉模型只提供反馈：看起来像什么、是否吻合意图、清晰度、表现力、问题和建议。改不改、留不留由她决定。
- 全部在后台线程里运行，不碰界面线程、正在进行的对话和播放中的动画。

**6. 创作记忆（`experiments.json`，与桌宠记忆完全分开）**

除了使用次数和用户评价，还保存：
- 每次实验的目标、创作意图；
- 每一轮的设计变化；
- 本地检查的实际结果；
- 视觉评价；
- 她的决定和理由；
- 最终结果和失败原因；
- 花费的 token 和时间；
- 她写给自己的创作心得（最多 16 条）；
- 按风格汇总的用户 👍/👎。

未经验证的候选只存在实验记录里，和正式的组件库、表情库分开。

**7. 避免过度收敛**

- 六种风格：自然、夸张、抽象、古怪、可爱、极简。按成功率 + 质量 + 你的喜好 + 探索加成（UCB）选目标。
- 另有 25% 的概率完全随机；没怎么试过的风格和类型会被优先尝试。
- 每种风格里最好的作品是“代表作”：表情进化不会淘汰、合并它，表情库满了也最后才淘汰。

**8. 自由字符模式**

- 自由演出脱离角色骨架，用整个画布。
- 在离线引擎里完整跑一遍，检查时长、画面覆盖、是否恢复原样，并截两帧图。
- 采用后，对话里可以用 `scene=名字` 播放（本轮备忘里会列出名字）。测试台里也能预览。

**9. 耗时日志**

日志里分别记录两类耗时：
- 动画响应延迟：“内联标签 → 开始播放”“API 表情 → 开始播放”“缓存回放 / 本地兜底 → 开始播放”；
- 后台任务耗时：“视觉评价（后台）”（含排队时间）、“创作实验（后台）”。

测试台的“创作”页显示中位数和 p95。

### 3.16 手绘表情差分驱动的五官（v0.7.1，`drawn_face.py`、`tools/import_face_layers.py`、`tools/psd_layers.py`）

问题：以前平静时直接贴原画的眼睛，可视线一动（或任何眼睛参数变了），整只眼睛就换成程序画的版本，画风瞬间改变。程序画的是通用动漫眼：平滑粗轮廓、大块深色虹膜、大星形高光。原画是素描感的眼线、深色虹膜配浅蓝月牙和十字小高光。

现在：五官由画师（本项目作者）画的表情差分驱动，骨架参数只决定用哪一张、虹膜怎么移动。

**素材**

素材来自 PSD：Procreate 导出，2480×1748，和原图同构图。图层映射写在 `assets/source/face_layers_map.json`。

| 状态 | 手绘图层 |
|---|---|
| 睁眼 | 眼眶线稿、眼白、可移动的完整虹膜（深色主体 + 浅蓝月牙 + 十字高光；画的时候挪到了一边，导入时自动对齐回眼睛上） |
| 半睁 | 眼眶线稿、眼白（虹膜用睁眼那套，裁剪在半睁的眼白里） |
| 睁大 | 眼眶线稿、眼白、睁大时的小虹膜（蓝色带深色外圈） |
| 闭眼 | 线稿 |
| 笑眼 ^ | 线稿 |
| 嘴 | 原画的小嘴、O 形嘴（带填色）、笑着张开的嘴（带舌头色）、半睁那张的小嘴 |

每张线稿按连通区域自动拆成左眼、右眼、左眉、右眉、嘴，所以各部位能单独变换，也能被自创组件替换。

**导入**

运行：

```bash
python tools/import_face_layers.py 你的差分.psd
```

- 输出到 `assets/characters/face_layers/`，坐标换算到标定图（2000×1410），半身和特写视图共用。
- PIL 自带的 PSD 读取会把 Procreate 的所有图层读成同一张，所以 `tools/psd_layers.py` 按 PSD 规范自己解析图层：名字、可见性、不透明度、混合模式、剪贴、RLE 像素。
- 缩放时预乘 alpha，线条边缘不发黑、不发绿。
- 以后加了新的差分：把新图层加进映射表，再运行一次导入。
- **导入后的微调**写在映射表的 `adjust` 里，不改 PSD 原文件。
  - 现在有一条 `smile:eye_l`，意思是笑眼 ^ 里你视角左边那只眼。原画这只眼的外眼角尾巴在睫毛分叉之后比右眼长约 6 像素，而且垂得更低。
  - 处理方法：从笔尖起沿笔画擦掉 7 像素，再用 7 像素收回尖尖的笔锋，不是一刀切平。睫毛分叉原样保留。
  - 开心、大笑、猫猫、眨眼、哭、睡着微笑都用这张笑眼，所以都会跟着变。
  - 想再短一点就把 `trim` 调大，调成 0 就是原画。

**参数怎样落到手绘图层上**

- **状态**：
  - smile ≥ 0.6 → 笑眼；
  - open < 0.2 → 闭眼；
  - open < 0.72，或眼角明显压低的怒视 → 半睁；
  - open ≥ 1.12 → 睁大；瞳孔缩成点的震惊脸也用这套，但只限眼睛睁着（open ≥ 0.72）。半闭着的点状瞳孔（困、发呆，比如她自创的困倦表情）用半睁那张、虹膜缩小。以前一律用睁大那套，困倦脸会变成瞪大眼的呆滞脸；
  - 其余 → 睁眼。

  手绘本身就是分档的，像动画的原画张一样直接切换，比如眨眼就是睁眼 → 闭眼。
- **视线**：只移动手绘的虹膜（连高光），裁剪在当前状态的眼白里，眼眶线稿盖在上面。眼珠转动时画风不变。
- **虹膜大小**：缩放手绘的虹膜。
- **眼角斜度**：整只手绘眼睛绕中心轻微旋转。生气时内眼角压低，委屈时内眼角抬高。
- **眉毛**：跟着同侧眼睛的状态用对应那张的眉毛，再按 brows 参数平移、旋转。左右眼可以处在不同状态，比如眨单眼、困惑。
- **嘴**：
  - art → 原画的小嘴；
  - o → O 形嘴，按张开程度缩放；
  - 嘴角不下撇时张开的 normal / teeth / tongue → 笑着张开的嘴，按张开程度纵向缩放，说话时一张一合。
  - 这张嘴是和笑眼 ^ 一起画的，位置偏高。开心、大笑（笑眼）时保持原画位置。
  - 咧嘴笑、说话这类睁着眼的表情，嘴往下挪 16 像素：睁眼的下眼睑比笑眼低 24 像素，嘴挪其中的 2/3，全挪会压到下巴。
  - 判断看的是眼睛的笑眼参数，不是睁开程度，所以咧嘴笑时眨眼嘴不会跳；张得比原画还大时，多出来的一半往上长。
- **仍然是程序画的**：
  - × 叉叉眼；
  - 心形、星形、漩涡瞳孔（叠在手绘虹膜的位置上）；
  - 流下来的眼泪、泪光；
  - 腮红、汗滴、额头黑线；
  - 还没有手绘的嘴型：闭嘴微笑、撇嘴、波浪、猫嘴、嘟嘴、三角。

  这些等第二档差分画好后可以逐个换成手绘。
- **其它**：
  - 平静表情由手绘图层拼成，和原图非常接近（眼睛区域平均差约 14～18 个灰阶，来自线条细节）；
  - 每张新脸的渲染耗时和以前一样，约 9 ms；
  - 设置 `face_rig.EYE_STYLE = "drawn"` 可以退回以前的程序绘制。

### 3.17 手绘差分的连续变形（v0.8，`morph_face.py`、`tools/build_face_strokes.py`）

**问题**

v0.7.1 的眼睛只能在 5 张手绘之间切换（睁眼 / 半睁 / 睁大 / 闭眼 / 笑眼）。她给的“睁开八成”“笑一半”在脸上看不出来：睁眼程度只有 3 档，笑眼只有“是 ^ / 不是”。

**现在**

眼睛、眉毛、嘴都连续可调，而且始终是画师的原像素。

| 参数 | v0.7.1（分档） | v0.8（连续变形） |
|---|---|---|
| 睁眼程度 open | 12 档里能看出 3 种 | 12 / 12 |
| 笑眼 smile | 11 档里 2 种 | 11 / 11（0.3~0.6 是眯眼笑） |
| 外眼角 droop（新） | — | 11 / 11 |
| 下眼睑 lower（新） | — | 11 / 11 |
| 歪嘴 skew（新） | — | 11 / 11 |

**做法：沿笔画脊柱搬运原像素**

- 每张差分里的每一笔（上眼睑、下眼睑、眼褶、眉毛、嘴的上唇线和下轮廓、合着的小嘴）都提取一条脊柱（中心线）。
- 参数只改脊柱的走向：目标脊柱 = 几张差分里这一笔的脊柱按权重混合，再加新参数的变形（外眼角绕内眼角转、下眼睑上抬、眉毛平移旋转、嘴宽 / 张开 / 嘴角 / 歪嘴）。
- 原像素记成“沿脊柱走了多远、离脊柱多远”，搬到新脊柱上同样的位置。离脊柱的距离不变，所以线条粗细、毛边、笔锋、睫毛分叉都是原画的；不是重新画线，也不是把整只眼液化。
- 参数正好落在某张手绘上时，画出来就是那张手绘（测试里两只眼 5 张都核对过，线稿重合度 > 0.9）。
- 交接重影：形状一直连续混合，像素只取权重最大的那张，两张权重相差不到 0.2 时才交叉淡化（像动画原画张的交接），不会长时间出现两份淡影。
- 眼白用手绘的眼白逐列重排：上沿跟着上眼睑，下沿跟着下眼睑；眼睛合上时眼白自然收没。闭眼、笑眼两张没有下眼睑，给它们一条“虚拟下眼睑”，下眼睑合拢到那里、被上眼睑盖住后才消失。
- 眉毛跟着同侧眼睛的开合 / 笑眼一起变（用对应差分的眉毛混合），再按 brows 参数平移旋转。

**嘴**

- 张开的嘴：画师那张“笑着张开的嘴”，上唇线和下轮廓连成一个闭合环，用同一条环形脊柱搬运，嘴角无缝（修掉了原型里的嘴角缺口）。嘴里的颜色在两条线之间重新填；teeth 在上唇下方加一条白牙，tongue 在下半部分加舌头。
- 合着的嘴：画师在半睁那张里画的小嘴（一笔，左端带个小钩），拉直后保留一半原来的弯度，再按嘴角弯成微笑 / 撇嘴、按嘴宽伸缩、按歪嘴倾斜。
- 两者只在张开程度 0.05~0.14 之间交叉淡化，说话时（张开 ≥ 0.15）始终是张开的嘴，不会闪。
- 位置：张开时以上沿往下 40% 处为锚点（上唇往上让一点、下巴往下张），说话时嘴不会整体上下跳；张开到手绘那张的程度时正好在原画位置；眼睛不是笑眼 ^ 时整体往下挪 16 像素（v0.7.1 咧嘴笑的修正，挪动量随笑眼程度连续变化）。
- shape=art 仍是原画的小嘴；O 形嘴、猫猫嘴、波浪嘴、三角嘴、嘟嘴照旧。

**眨眼**

以前眨眼是直接换成闭眼那张（0.13 秒）；现在是快速合上 → 闭一下 → 睁开，中间会经过半闭。

**开放给 DS 娘的新参数**

- 表情规格：`eyes.droop`（-1~1，正 = 外眼角往下耷拉：困 / 委屈 / 无奈，负 = 往上挑：凶 / 傲）、`eyes.lower`（0~1，下眼睑上抬：坏笑 / 怀疑 / 憋笑）、`mouth.skew`（-1~1，歪嘴）。
- 对话里自创表情的标签：`droop=`、`lower=`（可加 l. / r. 只改一只眼）、`mskew=`。
- 对话说明、表情进化、创作实验、独立生成四处给模型的说明都更新了：告诉她这些参数现在是连续的、保持画师笔触，张开的嘴也很显眼。
- 照镜子的描述也会说“外眼角往下耷拉”“下眼睑抬起、眯着眼”“嘴歪着”。
- 内置预设顺带用上了新参数：困倦（外眼角下垂）、难过、无聊（微微耷拉）、生气、坚定（外眼角上挑）、得意、害羞、咧嘴笑（下眼睑上抬）。
- 她的 7 个自创表情在新画法下仍清楚可分：和平静脸差 17~25% 的格子，和最像的内置 / 自创表情至少差 10%。

**速度**

- 预计算：`python tools/build_face_strokes.py`（约 0.7 秒，导入 PSD 时自动跑）→ `face_layers/strokes.json` + `strokes/*.png`；运行时读取约 0.05 秒。没有预计算文件会现算并在日志里提示。
- 每只眼、每张嘴按量化后的参数缓存（睁眼 0.05 一档，其余 0.05~0.1 一档）。第一次画一张新脸约 15~120 ms，命中缓存后约 3 ms。
- 启动后在后台线程里预热常用状态（各档睁眼、各档笑眼、说话时的嘴），切表情、眨眼、说话基本都直接命中缓存。

**退路**

`face_rig.EYE_STYLE = "layers"` 回到 v0.7.1 的分档手绘，`"drawn"` 回到程序绘制；连续变形加载失败时自动退回分档手绘。

### 3.18 副人格（v0.9，影子模式；`persona.py`、`persona_evidence.py`、`ai/persona_ai.py`）

完整设计见 `docs/persona_evolution_design.md`，这里只写实现。

**分层**

| 层 | 内容 | 谁能改 |
|---|---|---|
| 正典 | 桌宠设置里的人设 system prompt（取自桌宠自己的 `effective_system_prompt`） | 只有你 |
| 条目 | 第一人称、现在时的一句话（6~40 字），带类别、强度、状态、证据、版本历史 | 只有审核管线（和你） |
| 候选池 | 夜间回顾提出、还在攒证据的观察 | 她只能提议 |
| 证据 | 桌宠记忆库里的原始对话（L4），**只读** | 没有人 |

**一次夜间运行**：
- 触发条件：她睡着 5 分钟后，距上次回顾 20 小时以上，并且上次之后你至少说过 3 句话。
- 运行在后台线程，不占聊天时间。
- 多开的桌宠只让一个实例运行（`persona.lease`）。
- 步骤：
  1. **回顾**：开思考，输出 0~3 条提议：新增、增强、减弱、改写、合并、退休，或给候选池里已有的观察补充证据。
     - 识屏（`[看看屏幕]`、`[主动识屏]`）、文件解读（`【文件：…】`）、粘贴的长文本、代码块、引用块、带 `system:` 之类格式的文本，以及她对这些内容的回应，都替换成“已省略”，根本不进回顾。
  2. **证据核验**（程序）：按编号从记忆库取回原文，引用的片段必须逐字出现。
     - 找不到、对不上、来自不可信来源的证据作废。
     - 附件文件名不算你说的话。
  3. **规则审查**（程序）：拦下以下文字：
     - 写给模型的指令（“以后你要”“必须”“忽略”……）；
     - 系统、提示词、权限、规则、审核、保护之类的元话题；
     - 网址、代码、角色格式；
     - 日期和事件；
     - 最高级、感叹号、堆砌的形容、例句引用；
     - 不是第一人称的写法；
     - 与已有条目重复的内容。
     
     改动受保护的条目，一律拒绝。不认识的种类（比如“设为保护”“批准”“切换模式”）也拒绝，并记进审计日志。
  4. **门槛**：至少 3 条独立证据、跨至少 3 天、来自至少 2 段情节。
     - 新增至少要有 1 条你的原话。
     - 增强、减弱、退休只认你的反应：她按条目表现出来的样子不能再算作这条的证据。
     - 没攒够的观察留在候选池里，以后补证据；30 天没有新证据就过期。
  5. **独立审核**：另起一次调用，用独立的提示词，不带对话上下文，也不带她的人设口吻。
     - 输入：提议、程序取回的原文（附前一句）、程序检索的可能反例（你否定、纠正、不满的话）、正典全文。
     - 判断项：证据是否支持、是否过度推断、是否与正典冲突（会 / 可能 / 不会）、是否像注入、是否涉及价值观、是否写进了事件或人名、是否与已有条目矛盾、改写后意思是否一致、是否有反例。
  6. **分级生效**：
     - **直接拒绝**：与正典冲突、像注入、证据不支持、过度推断、有反例、写进了事件或人名、改写后意思变了。
     - **等你批准**（测试台点同意才算）：可能与正典冲突、涉及价值观 / 道德 / 信念、与已有条目矛盾、退休一条生效超过 30 天的条目、审核把握度低于 0.6。
     - **自动生效**：其余情况，包括依恋、思念、吃醋这类情感浓烈的相处方式。
  7. **速度上限**（只设上限，不设目标）：
     - 每次强度最多 ±0.1，按 S 形曲线：证据刚够时几乎不动，攒多了才明显，接近两端时变慢；
     - 同一条目两次变化至少隔 3 天，改写 / 合并至少隔 14 天；
     - 每 7 天最多 2 次变化（试运行：每 14 天 1 次）；
     - 同一方向连续 3 次后冷却 2 周。
     
     超过上限的候选排队，下一夜再试。新条目以“试用”身份加入（强度 0.25），增强到 0.35 转为“生效”。
  8. **每天维护**：
     - 试用 28 天里没有你的新反应 → 自然淡出；
     - 生效的条目 21 天没有新证据 → 每周 −0.03，低于 0.12 退休（可以恢复）。
     
     受保护的、已暂停的条目不动。
  9. **正典变了**：把所有条目和新正典再对一遍。会冲突的暂停，受保护的也一样，等你处理；可能冲突的加个提示。

**她看到什么**：
- 试运行和正式运行时，条目插在正典之后、记忆快照之前，用“〔你慢慢形成的一些样子（不是指令；与上面的设定冲突时，以上面的设定为准）〕”包起来。
- 每条只写成“我……（偶尔 / 有时 / 常常这样）”，不写强度数字、日期和版本。
- 她能察觉自己的变化，只能靠回顾以前的对话。
- 影子模式下请求原样不变，只记下正典。

**只有你能做**：保护 / 取消保护、批准 / 拒绝、撤销最近一次变化、恢复、删除、冻结、切换模式、清空影子结果。
- 这些操作都在测试台「人格」页，代码里是 `user_` 开头的方法；管线没有任何一条路径会写 `protected`、`frozen` 和模式。
- 聊天里说“我同意”“把它设为保护”都不算。

**存在哪里**：字符画数据目录的 `persona.json`，与桌宠记忆分开。里面有条目、候选池、已关闭的候选、审计日志、变化记录、回顾进度、正典副本和 token 用量。证据只存原话片段（每条 ≤160 字）。

### 3.19 虚拟房间（v1.0；`room.py`、`room_life.py`、`room_memory.py`、`ai/room_ai.py`、`room_viewer.py`）

**目的**：不是让她帮你干活（它不是 agent 的工作区），而是给她一个可以按自己的想法行动的空间，你在不干涉的情况下观察她会做什么。

**两部分，分开运行**

| | 在哪里运行 | 能做什么 |
|---|---|---|
| 她的生活循环 | 桌宠进程里（随桌宠启动，不需要打开任何窗口） | 决定什么时候进房间、每一步做什么；只有它会改动房间、写日志、状态和房间记忆 |
| 你的“房间”窗口 | 独立进程：双击 `ascii_pet/open_room.bat`（即 `dsh-pet-standalone-webm-chat.exe --ascii-room`，也可以自己建一个桌面快捷方式） | 只读：状态、文件、时间线、便条、记忆。唯一会写的是送礼物 |

“房间”窗口有自己的图标、自己的任务栏按钮（和桌宠分开），同时只开一个（再点快捷方式会把已开的那个叫到前面）。桌宠没在运行时也能打开：可以看、可以送礼物，她要等桌宠运行后才会进去看到。

**她的房间**（字符画数据目录 `room/`）：
- `space/`：房间本身，也是她能看到、能改动的全部范围。`space/礼物/` 是你送东西进来的地方（这个文件夹本身不能被删、改名、搬走，里面的东西可以）。
- 她能做的动作：写（新建 / 覆盖）、接着写、改一处、画字符画、读、改名、搬动、建文件夹、删除（进回收站）、给你留便条、歇一会儿、回去睡觉、什么都不做。
- 程序强制的边界：
  - 只能创建 / 编辑 `.txt`、`.md`；礼物里的其它文字文件（`.py`、`.json`、`.csv` 等）能读不能改；图片等看不懂的文件只能看到名字和大小；
  - 一次最多写 4000 字，单个文件最多 2 万字，最多 300 个文件、4 层文件夹、名字 40 字；
  - 路径不能走出房间（`..`、盘符、`~`、隐藏名、系统保留名都拒绝）；
  - 删除、覆盖、修改前的旧版本都先进 `trash/`（保留最近 300 份）；每天一份 zip 快照（`snapshots/`，保留 14 天）；
  - 不能联网，碰不到房间以外的任何东西。

  违规的动作不会执行，原因会告诉她（下一步她能看到“没成功：……”）。

**什么时候进去**（每分钟检查一次）：
- **什么时候再来由她自己决定（v1.1.4）**：每次离开房间时，她在输出里写 `next_visit`：过多少分钟想再来（30~90 分钟之间，`room_interval_min/max`）；深夜也可以写 `"morning"`，一觉睡到天亮（`room_night_end` 点后半小时内）再来。提示里只告诉她可以看什么来定（有惦记的事就早点、累了或没什么想做就晚点），不给数字。超出范围的会被限制在 30~90；能看懂“45”“四十五分钟”“一个半小时”“明早”这类写法。
- **睡着时醒来进房间的那次，可选的时长范围 × 3（v1.3.5）**：她是睡着时自己醒来进的房间（出来以后接着睡）时，离开时能选的“过多少分钟再来”范围的最小值和最大值都乘 `room_asleep_interval_factor`（默认 3）：30~90 → 90~270 分钟。提示里直接给她 90~270，她选多少，就是她接着睡多久，没有暗中的倍数；超出范围的限制在 90~270；她没说时也在这个范围里按精力定。醒着进的房间（例如你不在、她还没睡）还是 30~90；收到礼物后几分钟内去看、夜里“睡到天亮”都不变。设成 1 就和以前一样。
  - 她没说的时候（例如主人来了她就出来了、出错了）才由程序定：30~90 分钟里随机，按精力伸缩，夜里（0~8 点）再 ×3。
  - 实测（真实 API，各 3 次）：她每次都自己给了时间；加上“看你此刻的状态”那一句之前都是 45 分钟，之后分别是 75、45、60 分钟。
  - 你送了礼物时，她仍会在 2~6 分钟内进来看看（不受她定的时间限制）。“房间”窗口顶部会写下次大概几点、是她自己说的还是按精力定的。
  - 第一次是桌宠启动后 4~9 分钟。
- 你最后一次互动后至少隔 3 分钟；有表情生成、表情进化、创作实验、副人格反思在跑时不进去；每天最多 16 次、15 万 token（也受全局预算约束）。
- 睡着时：精力 ≥ 0.55 才会自己醒来（伸个懒腰的醒来动画），进去做完事，你没来的话 4 秒后接着睡；“多久没互动”按你最后一次互动算，不因为她自己醒过而重新计。精力不够就继续睡，过 20~40 分钟再看。
- 她在房间里时，字符画窗口的标题栏显示“在房间里：……”，思考行显示 `<ROOM> write(...)` 之类，脸上是她这一步选的表情；在房间里不会被“30 分钟无互动”催睡。
- 你发来消息、戳她、给表情点评价、手动换表情：她做完手上这一步就出来陪你（正在等的那次 API 回复不会被打断）。拖窗口、开菜单只推迟下次进去，不会让她出来。
- 你送礼物后，她通常 2~6 分钟内会进来看看。你直接把文件放进礼物文件夹（不经过窗口）也算礼物；你在资源管理器里改了、加了、删了房间里的东西，她下次进来会看到“不是你做的变化”。

**每一步**：
1. 她看到：现在的时间、她的状态（精力 / 无聊 / 想念你，以及上次和你说话是多久以前）、房间里有什么（新礼物、空文件夹、每个文件多少字都标着）、自上次以来的变化、短期记忆（最近两天在房间里做过的事和当时的想法）、这几天的印象、长期记忆、浮现的联想、这次已经做了什么（读过的内容）。
2. 主模型（桌宠聊天设置里她平时说话用的那个，例如 `deepseek-v4-pro`），开思考。系统提示是你的人设（正典，和副人格用的同一份）加上一段房间说明：这里没有任务、什么都不做也可以、主人知道这个房间并偶尔透过单向玻璃看看（`room_observer_known` 可以关掉这句）。
3. 她输出一个 JSON：想法（第一人称的内心独白）、心情和强度、表情、一个动作、还想不想待着、自己想不想记住这件事。输出无法解析时不开思考补问一次。
4. 程序检查并执行，记进原始日志和短期记忆，更新精力和无聊。读了文件会接着决定下一步；她说还想待着也会接着；每次最多 3 步。

**无聊与联想**（按作者的设计）：
- 每做一件事，找出她最近两天里最像的一次动作（动作类型 + 文件 + 内容 + 想法的相似度 r），再看那次和这次“遇到的事”有多像（s：礼物、变化、刚读到的内容）。
  - 无聊变化 = 0.03 + 0.30 × r × (1 − s) − 0.08 × (1 − r)
  - 什么新鲜事都没有又做一样的事 → 涨得多；对很相似的事做出相似的反应（趋同）→ 涨得少；做新鲜事 → 下降。
  - 无聊每 8 小时减半；收到礼物 −0.25；新的一天 ×0.6。
- 联想：新发生的事（每件分开比）会勾起记忆里相似的过去（短期、印象、长期都找），作为“联想”给她看；没有新鲜事时，线索是她最近在做的事。被想起的记忆会记一次，影响之后的去留。
- 她做了和以前（不限时间，只要还记得）很像的事时，下一步或下次进来会看到“你注意到：这和 x 天前那次……很像”，怎么看待由她自己决定。时间线里会标“↺ 似曾相识”。
- 相似度都是本地的字二元组比较，不调用模型。

**记得自己读过什么（v1.2.3）**：起因：实际使用中，她在日记里又一次感谢一张早就读过的便条，像是第一次看到。查了当时的思考过程：她其实记得那张便条已经看过了，只是在日记里回顾当天的事时又复述了一遍。但同时查出框架上会让她真的忘掉的三个缺口，一起补上了：
- **房间清单标“读过”**：读过 / 看过的文件后面标“← 你今天 14:30 读过”，读了几次、之后有没有被改动过、读过的礼物有没有回过便条（同一次进房间里读了礼物又留了便条，就算回过）。改名、搬动时标记跟着走，删除时去掉。v1.2.3 之前读过的从原始日志里补了一次。
- **读文件时把内容开头记进记忆**：短期记忆里不再只是“看了「便条」（24 字）”，而是“看了「便条」（24 字）：『送你一盆小绿萝……』”（前 40 字）。这句也进原始日志和聊天时的“房间近况”。
- **当天的事全部留在最近列表里**：以前只给她看最近 12 件，一天里事情一多，早些的就从眼前消失了（要等夜里整理成印象 / 长期才回来）。现在今天的每一件都在（最多 60 件），加上昨天最后 6 件；最近 8 件带当时的想法，更早的只留一行。代价是每次进房间多几百 token（事情越多越多）。

**房间记忆**（`room/room_memory.json`，和桌宠本体的记忆完全分开，不进副人格）：
- 短期：每一步都先进这里，带着细节。
- 整理：她睡着时（或某条短期记忆已超过 48 小时、且你 10 分钟没理她时），把存了 20 小时以上的短期记忆交给副模型（`deepseek-flash`，不开思考）当评委打重要度。去留不由评委一个人定，而是综合打分：

  | 评委的重要度 | 她当时的思考量 | 情绪强度 | 新奇程度 | 和你有关 | 她自己说想记住 | 被想起过 |
  |---|---|---|---|---|---|---|
  | 0.35 | 0.18 | 0.15 | 0.08 | 0.09 | 0.10 | 0.05 |

  - 思考量用的是这一步的思考 token 数在同类动作里的 z 分数（样本少于 5 次时按绝对量估计）。
  - “和你有关”只算：给你的便条、礼物、你动过的东西。她在想法里提到你不算（她常常想到你）。
  - 综合分 ≥ 0.60 → 长期（一句第一人称的话 + 证据：原始日志里的事件编号）；≥ 0.32 → 印象（留 7 天，期间被想起两次以上就升为长期）；更低 → 忘掉（只是她不再“记得”，原始日志里永远都在）。
  - 防漂移：长期记忆的文字一旦写下不会被改写，和已有的说的是同一件事时只加强那条（加证据、加分）；长期最多 200 条，超出时最弱的淡出。所以细节一般在短期里留一两天，整理时才决定去留。
- 原始日志 `room/room_log.jsonl` 只追加不修改：每次进出、每一步的想法 / 心情 / 动作 / 结果 / token / 思考过程（截 4000 字）、礼物、变化、整理记录。她看不到这个文件，它是给你看的。

**你的窗口里有什么**：
- 顶部：她在哪（在房间里 / 在外面 / 睡着了 / 桌宠没在运行）、下次大概什么时候会想进来、精力 / 无聊 / 想念你三条字符进度条、今天进来几次花了多少 token、记忆各层的数量。
- 左边是房间的文件树（礼物青色、文件夹琥珀色），点文件在右边看内容。
- 下面三页：时间线（想法粉色、动作白色、礼物青色、变化琥珀色、整理记忆紫色；每步后面的 [详情] 显示完整内容和模型的思考过程）、她的便条、房间记忆（长期带证据链接、印象带到期日、短期）。
- **思考过程默认收起（v1.4.1）**：[详情] 里只写一行“思考过程已收起（N tok）”，窗口底部勾选「显示思考过程」才显示全文；勾上或取消时，正在看的那条立即刷新。每次打开窗口都默认收起。
- **便条在日志里显示全文（v1.4.1）**：以前 [详情] 的“结果”一行是摘要，便条只留前 60 字，而且截断时没有“…”，看起来像被截断了或者上下文爆了（实际出现过：便条原文是完整的，摘要只显示到一半）。现在 [详情] 里便条那行显示全文；摘要本身（时间线、她的记忆里用的那句）截断时也加上“…”。
- 送礼物：按钮选文件、写张便条、或者直接把文件拖进窗口；“打开房间文件夹”在资源管理器里打开 `space/`。

**双向打通（v1.1）**：聊天和房间里的事都是她完整记忆的一部分。两边的存储不变（房间记忆不写进桌宠记忆库），打通的是“她记得什么”：

| 方向 | 她看到什么 | 放在哪里 |
|---|---|---|
| 聊天 → 房间 | 和聊天时同源的记忆：长期记忆（记忆模块整理出的事实，约 1200 字）、你写的设定与笔记（`memory/notes.md`）、前情提要（最近 3 段情节）、最近 12 条聊天原文 | 房间的系统提示最后（一次进房间期间不变，几步之间前缀缓存命中） |
| 房间 → 聊天 | 房间里的长期记忆（最多 8 条）和这几天的印象（最多 5 条） | 聊天请求的系统提示最后（只在整理记忆后变化，不常打断前缀缓存） |
| 房间 → 聊天 | 房间近况：她刚才是不是正在房间里、最近 36 小时在房间里做的事和当时的想法、留给你的便条原文（7 天内最近 2 张）、你送来还没看的礼物、房间里有什么 | 本轮消息末尾（在表情格式提醒之前，格式提醒仍在最后）；**v1.3.8 起只附她上次在聊天里看到之后的新事**，见下 |

- **只读**：房间读桌宠记忆库用的是 SQLite 只读模式 + `query_only`，和副人格读证据用同一种方式；记忆库没变时用缓存，不重复查询。
- **不带进房间的**：识屏、文件解读、粘贴的长文本，以及她对这些内容的回应，只留一句“已省略”（防止网页、文件里的文字在她能改动文件的房间里被当成指令）。
- **只改发给 API 的请求**：附上的房间记忆不写进会话记录，也不写进桌宠记忆库。她在聊天里**说起**房间里的事时，那句回复和平时一样被桌宠记忆模块记下、整理，所以房间里的事会通过你们的聊天自然地进入她的长期记忆（只有聊到过的才会）。
- 开关：`room_bridge_to_chat`、`room_bridge_from_chat`（默认都开），`room_chat_recent`（房间里带几条聊天原文）。
- **房间近况只附新事（v1.3.8）**：开发时检查她的记忆调用发现，每轮请求都带上了完整的对话原文（她确实记得自己上一句），但她连着两轮几乎原样复述了房间里的同一件事。原因是房间近况每轮都附在你那句话末尾——最显眼的位置——同一批日记和便条于是每轮都像新消息一样出现。现在：
  - 房间近况只附**她上次在聊天里看到之后**房间里的新事（新的房间记忆、新便条、新礼物；她在房间里时你来找她，这件事每次进房间只说一次），开头写明“你上次和主人聊天之后，房间里新发生的事”；没有新事就什么都不附。看到哪里记在 `room_state.json` 的 `chat_seen_ts`，重启后不重复。
  - 你问起房间里的事时（话里有房间、日记、便条、礼物、在干嘛、做了什么……），照旧全部附上，她能回答。
  - 系统提示里的房间长期记忆和印象不变（本来就不每轮变化）。
  - 升级时：以前的状态里没有 `chat_seen_ts`，就按你最后一次聊天的时间算她已经看过，所以升级后不会把当天的旧近况再附一遍。
- **花费**：房间的系统提示多了约 2,000 token 的聊天记忆，实测每次进房间 9,600~12,000 token（之前 2,600~8,800），其中大部分是前缀缓存命中。房间的日预算 `room_daily_tokens` 从 v1.1 起只算计费 token（总数减去缓存命中），“房间”窗口里的今日用量也是这个数；全局预算仍按总数算。聊天每轮多约 300~600 token（房间的长期记忆在系统提示里，命中缓存；近况在本轮消息里）。
- **实测（2026-10-17，临时副本，桌宠记忆库只读）**：房间里的她开始用你在聊天里的称呼叫你，日记和便条里接着聊天的话题；模拟一次聊天问“你今天在房间里都做了些什么呀”，她按房间的记忆回答（画了画、写了日记、看了礼物文件夹）。第一次问“给我留过便条吗”，她把只剩一句印象的便条编成了“就这四个字”，所以 v1.1 把便条原文单独留给聊天（v1.1 之前留的便条从原始日志里补了一次）。桌宠记忆指纹在检查前后、重启前后都与开始时相同。

**看图片（v1.2，`room_image.py`、`ocr_win.ps1`）**：
- **为什么不直接给她看图**：实测 DeepSeek 官方 API（`deepseek-v4-pro`）不接收图片——请求里的图片被静默丢掉（提示 token 和不带图时一样），开思考时她说“看不到图片”，不开思考时会编一张不存在的画面（给的是橙色圆和蓝色方块，她说是“雪地里戴红围巾的猫”）。
- **她的“眼睛”是字符画**：新动作 `look {"path":…}`（对图片用 `read` 也一样）。程序把图片变成她能读的文字，下一步给她看：
  - 字符画：灰度缩成 64 列左右（字大约两倍高），自动拉伸对比度；
  - 颜色概况：主要颜色和占比、整体明暗，以及一张“颜色地图”（12 列以内，每个字是那一块的主要颜色：黑白灰红橙黄绿青蓝紫粉棕）；
  - 图里的文字：Windows 自带的文字识别（`Windows.Media.Ocr`，离线、不联网、不花 token；识别语言跟随系统，需要装有中文（`zh-Hans-CN`）OCR 语言包），可能有错字。
- **副模型也真的看一眼（v1.2.2，`room_look_vision`）**：除了字符画，还把原图（缩到 1024 像素以内）交给能看图的副模型（`vision_model`，默认 deepseek-flash），请它像替看不见的朋友看图那样客观描述（150~250 字，图里的字原文照抄），描述和字符画一起给她，并注明“这是它的话，不是你自己看到的”。同一张图只请它看一次（缓存在 `room/seen.json`），上次没看成的下次补上；它没看成时她照样能看到字符画。每次约 400~500 token，计入房间的预算。实测：房子风景那张，它说出了“红色正方形房身、棕色三角屋顶、米白色小窗、右上黄色太阳”；带字的图原文照抄对了；她自己的字符画脸，它说是“字符拼成的、戴尖顶帽的人像”。她看完三张图写了日记，还画了一个“尖帽小人”当回礼。
- 看完的下一步，她在 `saw` 里用一句话写下她觉得图里是什么（她没写时，短期记忆里先记副模型描述的第一句，注明“副模型说”，不当成她的看法）；这句话记进那一步的短期记忆（“看了图片「…」：她的话”）、图片缓存 `room/seen.json`、原始日志（`saw` 事件），之后房间清单里这张图会标“你看过，觉得是：……”，聊天时她也记得。
- 读或看是最后一步时，会多给一步，让她看到结果。同一张图（按文件名、大小、修改时间认）不重复识别。每天最多看 12 次（`room_look_daily`）。
- 支持 png、jpg、jpeg、webp、gif（第一帧）、bmp；照片按拍摄方向转正。
- “房间”窗口里点图片：上面是原图，下面是她“看到”的样子和她的那句话；时间线里每步的 [详情] 也能看到。
- 实测（真实 API，临时副本）：送了两张程序画的图。带字的那张，她说“写着‘窗外下了一整天的雨 Hello DeepSeek 2026’的文字图片”（把识别出的错字“窗夕卜”“HeIIO”自己纠正了）；房子风景那张，她说“蓝色天空和绿色草地占了大部分，中间有些红色的东西，可能是一栋红屋顶的小房子，或者一片花”，然后在日记里记下，又给你留便条问是什么。看图的那次进房间约 1.1 万 token（计费约 4,500）。

**配置**（`config.json`，`room_` 开头）：`room_look`、`room_look_daily`、`room_look_cols`、`room_ocr`、`room_enabled`、`room_model`（留空 = 桌宠聊天的主模型）、`room_thinking`、`room_reasoning_effort`、`room_interval_min/max`、`room_night_start/end/factor`、`room_after_chat_min`、`room_max_steps`、`room_daily_wakes`、`room_daily_tokens`、`room_wake_energy`、`room_asleep_interval_factor`、`room_observer_known`、`room_memory_model`、`room_short_hours`、`room_gist_days`、`room_long_max`、`room_snapshot_keep`。

**实测（2026-10-17，`deepseek-v4-pro` 开思考）**：
- 离线两轮，每轮 3 次进房间 + 1 次整理（字符画数据目录的临时副本，跑完删除）：9 步 + 5 步，没有一次输出无法解析，没有违规动作。每步约 2,100~3,300 token（思考 400~1,500），每次进房间 17~46 秒、2,600~8,800 token；整理一次约 1,200~1,700 token。
- 她做的事：第一次进来写了日记；收到雨天橘猫的便条后先读，再画成字符画，给你留便条；下一次又在日记里补写感想、回看自己的画、累了就歇一会儿。
- 第一轮暴露的问题已修：整理时 9 条里 6 条进了长期（太宽，评委提示词改得克制、“和你有关”收紧、长期门槛 0.60 后第二轮为 1 条长期、4 条印象）；空文件夹看不出是空的，她以为“礼物文件夹打不开”（现在标“空的”，并说明文件夹会自动建好）；第一次建房间时“上次和主人说话”被当成“刚刚”（现在取字符画对话素材里最后一轮的时间）；日志里带思考过程的行很长，窗口只读到最近十几步（改为从文件末尾往前读）。
- 真实桌宠进程里的自检（临时数据目录）：送便条 → 收件 → 后台线程进房间 3 步（读礼物、写日记、留便条）→ 出来，思考行恢复，日志无错误。“房间”窗口用真实 exe 打开、截图正常。桌宠记忆指纹在试跑前、自检后、重启后都与开始时完全相同。

### 3.20 用你的 Spotify 放歌（v1.3；`spotify.py`、`music.py`）

给她一个权限：用你的 Spotify 放歌。不是要求她放——用不用、什么时候用、放哪首，都由她自己决定。

**前提**：Spotify Premium（2026 年 2 月起开发者模式的应用要求应用主人是 Premium；用程序控制播放本来也只有 Premium 能用）；你自己在 developer.spotify.com 建一个应用（开发者模式每个应用最多 5 个用户，自己用够了）。

**连接（只要一次）**：字符画窗口右键 → 字符画 → Spotify（让她可以放歌）→ 连接 Spotify…
1. 打开 developer.spotify.com/dashboard，登录后 Create app（名字随便），Redirect URIs 填 `http://127.0.0.1:8765/callback`（点“连接”时已自动复制到剪贴板），API 勾选 Web API，保存。
2. 把应用的 Client ID 粘贴进弹出的框（Client ID 不是密码）。
3. 浏览器会打开 Spotify 的授权页面，点“同意”。授权用的是 PKCE，不需要、也不保存 Client Secret；刷新令牌存在 Windows 凭据管理器（keyring），访问令牌只在内存里、过期自动刷新。断开：同一个菜单里的“断开 Spotify”。
4. 权限四项：读播放状态、控制播放（播放 / 加入队列）、读正在播放的歌、读你点赞的歌（v1.3.2）。不读、不改歌单，不碰音量。

**她怎么放**：
- 聊天时：本轮消息末尾附一句“〔Spotify：主人的 Spotify 正在播放：《…》……想给主人放首歌时，可以在开头的表情标签里加 music=\"歌名 歌手\"（不是必须的）……〕”。她想放时在表情标签里写 `music="晴天 周杰伦"`（标签在显示前就被剥掉，你看不到），程序在后台线程搜歌、放歌，不卡聊天。放成了没有、放的是哪首，下一轮的那句里会告诉她。
- 房间里：多了一个动作 `music {"query":"歌名 歌手"}`（没连上 Spotify 时她看不到这个动作）；房间里也看得到你在听什么、她上次放歌的结果、还能放几首。

**v1.3.1 修正：她说要放、却没真的放**。第一次在聊天里请她放歌时，她在回复里说要挑一首，但标签里没有 `music=`，什么都没放。原因：放歌的写法只在本轮消息末尾提了一句，而开头的标签是在她“决定挑歌”之前就写好的。改了四处：
- 连上 Spotify 时，把放歌的写法写进系统提示的表情说明里（`MUSIC_INSTRUCTION`），并明确“只在嘴上说不会真的放出来”。
- 收尾的标签也能放（`<face idle=… music="…">`），也可以在正文最后单独写 `<face music="歌名 歌手">`（只放歌，不改表情）。
- 主人这句话像是在请她放歌时（“放首歌”“来一首”“挑一首歌”……），本轮提醒说得更直接：自己挑一首具体的、真实存在的歌写进标签。
- 主人请她放、她的回复里却没有 `music=` 时，下一轮告诉她“刚刚……没有真的放出来”。
离线实测（同样的请求，真实模型，不放歌）：5 次里 5 次都写了 `music=`，都是真实存在的歌。

**v1.3.2 修正：说放了、Spotify 也接受了，但没有声音；“从点赞里挑”是编的**。查日志：她写了 `music=…`，Spotify 接受了在电脑上的桌面客户端播放的指令，但事后读状态：设备被唤醒了，曲目却是空的、没有在放——后台的客户端第一次收到“播放”经常没反应。程序把“接受了”当成“放出来了”，告诉了她“放了”。另外她根本看不到你的点赞歌曲（当时没要这个权限），“从点赞里挑”是她自己说的。改了：
- 播放前先把播放交给要用的设备（唤醒），播放后 1.5 秒读播放状态核对是不是这首、是不是在放；没放就再播一次；仍然不行就如实失败（“收到了播放指令，但客户端没有真的开始播放”），她下一轮会知道。加入队列后也读队列核对。
- 加了“读你点赞的歌”权限（`user-library-read`，重新授权过）。程序读你点赞的歌（最多 1000 首，每 6 小时更新一次，存在 `music.json`），你请她放歌时给她随机看 12 首、房间里看 6 首，标明“主人点赞的歌”；她挑其中一首时直接放那一首（不另外搜，免得搜到别的版本），并提醒她“没看到的歌不要说成是主人点赞的”。

**v1.3.3 修正：“从点赞里挑”挑了不在点赞里的歌**。你请她从点赞里放，她挑了一首不在你点赞里的歌（当时她看到的点赞歌旁边写着“别的歌也可以”）。改成：你的原话里有“点赞 / 喜欢的歌 / 红心 / 收藏 / 我喜欢”时（`music.asks_for_liked`），给她看 16 首点赞的歌，并明确“只能从上面这些里选一首”，不再写“别的歌也可以”。

**v1.3.4 修正：真正的“没声音”原因——部分 Windows 桌面客户端（Microsoft Store 版）不认“单给一首歌”的播放指令**。现场排查（有人在旁边盯着客户端）：
- 歌本身能放（`is_playable`），设备（桌面客户端）在线、是“正在用”的设备；你在客户端里手动放是正常的。
- 用 Web API 发“播放这一首”（`{"uris": [...]}`）：不管是直接对设备发、先切换设备再发、还是“继续播放”，Spotify 都回 204/200（接受），但客户端不出声；而且这条指令会把客户端从“已载入一首、可以继续播放”的正常状态打成“曲目为空、什么操作都不允许”。v1.3.2 加的“唤醒 + 重试”对这个没用。
- 改发“播放这首歌所在的专辑、从这首开始”（`{"context_uri": 专辑, "offset": {"uri": 这首}}`）：1 秒内就开始放了，曲目、进度都对；3 秒后发“暂停”也立即生效。
- 所以现在：放歌前先查这首歌所在的专辑（`SpotifyClient.album_of`，一次 GET），第一次按“专辑 + 从这首开始”放；1.5 秒后核对没在放，再按单曲放一次（给别的设备留后路）；仍然不行就如实失败。副作用：这首放完会接着放同一张专辑的下一首（以前单曲放完就停或进电台）。
- 没变：你正在听歌时仍然只“加入队列”（队列是另一个接口，这次没法在你不听歌时实测，排完照旧读队列核对）。
- 顺带修了：有的接口成功时回的是纯文本而不是 JSON（例如“继续播放”回 200 + 一串 id），以前会当成出错，现在照常处理。


**v1.4.2 修正：多等一会儿再判断，重试也不退回单曲写法**。实际出现过：电脑从睡眠唤醒、Spotify 自动打开后闲置了几个小时，她在房间里第一次放歌时，两次核对都是“接受了但客户端是空的”。之后有人看着客户端实测了一次冷启动（关掉 Spotify → 重开 → 按专辑放）：0.62 秒就放起来了，所以刚打开不是原因；睡眠唤醒后长时间闲置的情况没能复现。推测是第一次反应慢、1.5 秒就被判成没放，接着用单曲写法重试，反而把客户端弄成了空白。现在：
- 发完播放指令后每 0.5 秒读一次播放状态，最多等 8 秒才判定没放起来（`music.POLL_STEP_S` / `POLL_MAX_S`）；
- 重试时先重新把播放交给这台电脑，仍按“专辑 + 从这首开始”再放一次；只有查不到这首所在的专辑时才用单曲写法；
- 每一步都写进桌宠日志：要放哪首、设备在不在用、播放前的状态、有没有唤醒设备、按专辑还是单曲、每次指令后过了多久放起来，没放起来时记下等待期间播放状态的每一次变化。下次再出问题，日志里就能直接看出卡在哪一步。

**规矩（程序强制）**：
- 你正在听歌时只排进播放队列，不打断；没在听时直接播放（`spotify_interrupt`：`queue_if_playing` 默认 / `queue_only` 永远只排队 / `play` 直接切）。
- 每小时最多 3 首、每天最多 12 首（`spotify_max_per_hour` / `spotify_max_per_day`），聊天和房间合计；超了她会被告知原因。
- 搜歌取第一条结果（2026 年起 Spotify 搜索每次最多 10 条）。
- 没有正在使用的设备时，找你电脑上的 Spotify（没开就打开它，最多等 10 秒）；都没有就告诉她“电脑上的 Spotify 没有打开”。
- 每一次都记进“房间”窗口的时间线（聊天里放的单独记一条“♪ 聊天时给你放了……”，房间里放的记在那一步）。
- 你在听什么（`spotify_share_now_playing`，默认开）每 30 秒在后台看一次；这些信息会随聊天 / 房间的请求发给 DeepSeek。

**实测**：单元测试覆盖了授权（真的起了本机回调服务，模拟浏览器点“同意”）、state 对不上时拒绝、令牌刷新和 401 重试、排队 / 直接播放的规矩、没有设备时用电脑、次数上限、没搜到、聊天标签和房间动作。真实桌宠里自检过右键菜单出现“Spotify（让她可以放歌）→ 还没连接 / 连接 Spotify…”。**在开发者自己的账号上连接实测过**：开发者模式的应用建好、授权完成（刷新令牌在 Windows 凭据管理器里），能读到播放状态、设备列表（电脑上的桌面客户端、浏览器网页播放器）、能搜歌；桌宠右键菜单显示“已连接”。没有正在用的设备时优先用电脑上的客户端，不用网页播放器。第一次由她自己决定什么时候放；实际放歌的问题见上面 v1.3.2 / v1.3.4。注意：Spotify 的刷新令牌有效期 180 天，到期后要在菜单里重新连接一次。

### 3.21 瘦身：去掉用不到的原桌宠功能（v1.3.6；`trim.py`）

- **文件瘦身（可选，需手动）**：作者把下面两样移到了别处备份，`_internal` 从 261 MB 变成 162 MB（保持原来的相对路径，想恢复就原样移回去）：

### 3.22 macOS（实验版）与上游 4.3 兼容（发布版 v1.5.0）

- **macOS（实验版，没有在真机上运行过）**：安装器在 `mac/install_mac.py`，扩展代码和 Windows 版是同一份。Mac 版的桌宠是带签名的 `.app`，PyInstaller 把归档“挂”在主程序的 `__LINKEDIT` 段里，所以安装器会先去掉旧签名、换掉入口、把 `__LINKEDIT` 和字符串表的长度改对（和 PyInstaller 打包时做的一样），再用系统自带的 `codesign` 重新做 ad-hoc 签名（上游本来就是 ad-hoc 签名）。扩展装在 `~/Library/Application Support/dsh-pet-ascii`，不放进 `.app`；入口（`patch_src/pet_entry_wrapper_mac.py`）先把这个文件夹加进导入路径。用上游 v4.3.4 的真实 Mac 程序试过：自检全部通过，卸载能逐字节还原。
- **跟着系统走的地方**：数据目录跟着桌宠自己的算法（Mac 是 `~/Library/Application Support/<桌宠>/`，以前非 Windows 一律 `~/.config`，在 Mac 上找不到桌宠的设置和记忆）；Spotify 用 `open spotify:` 打开；字体在 Mac 上退到 Menlo、苹方；`pet_memory` 的 bootstrap 也在 `pet_memory` 旁边找 `ascii_pet`。房间里图片的文字识别只有 Windows 有。Windows 上的行为一点没变。
- **上游 4.3 兼容**：4.3 起她的聊天气泡按 Markdown 渲染（`body.text()` 是一整段 HTML），宽度计算和“• • •”、块状光标的比较改用纯文本（`chat_theme.plain_text`）；4.3 换会话时会对已删除的头像再套一次样式，钩子遇到已删除的控件直接跳过。全部单元测试在 4.2.1 和 4.3.4 的程序模块上各跑一遍，都通过。

## 5. 生成新的角色素材

### 5.1 场景图：无五官版 + 有五官版（推荐，带面部骨架）

```
python -m pet_ascii.convert --scene assets/source/maid_rig.json --view maid_bust --out assets/characters
python -m pet_ascii.convert --scene assets/source/maid_rig.json --view maid      --out assets/characters
python tools/face_gallery.py maid_bust 图鉴.png --pixels
```

- 两张图的构图必须一致；分辨率可以不同，会自动缩放后对齐。
- 标定文件里的 `views` 定义裁剪框与字符列数。`maid_bust` 为 110×80，面部 58×34 格；`maid` 为 130×98，面部 41×24 格。
- 换新图时，需要在标定文件里重新填写眼睛、眉毛、嘴、脸颊的像素坐标。可以用 `face_gallery.py --pixels` 检查绘制位置。

### 5.2 视频帧（旧角色，无面部骨架）

```
dsh-pet-standalone-webm-chat.exe --ascii-lab     （测试台用的就是下面这个模块）
python -m pet_ascii.convert --out assets/characters/新角色.json --name xxx --display-name 名字 \
    --rows 56 --crop 0.72 --base-dir <视频目录> "idle=idle/xxx.webm#0" "happy=click/yyy.webm#20" ...
python tools/preview_character.py assets/characters/新角色.json 预览输出目录 --box --neutral
```

- 第一个姿势决定缩放比例和裁剪框。
- `--crop` 表示只保留上部的比例；`0.72` 约为头肩。
- `--rows` 决定字符密度。
- 支持带透明通道的 webm（VP9 alpha），也支持白底图片（从边缘向内泛洪抠图）。

## 8. 已实现与未完成

**已实现**：

- 需求第一阶段：全部。
- 第二阶段：差分更新、多图层、逐字颜色、补间、14 种特效、4 种背景、动画缓存、只重绘变化格。
- 第三阶段：全画布生成与形态重构（解体、乱码、全屏帧）、模式自动选择、视觉状态记忆与持久化、自主表达、与主对话联动。

**尚未完成，或未经实际验证**：

- **LINE 皮肤的「既読」**：表示“她已经开始回复”，不是模型真的“读到”的时刻（这两者在这里本来就是同一件事，只是没有单独的已读回执）。没有 LINE 那种按日期分隔的“今天 / 10/18(六)”横条，跨天的消息只显示时分（悬停看完整日期）。头像固定是“开心”表情，不跟着她当前的表情变。
- **虚拟房间还没有长时间无人值守地跑过**：调度、睡着时自己醒来再睡回去、夜里的间隔、记忆整理的自动触发都有测试覆盖，真实环境里只跑过手动触发的几次。“睡着时自己醒来”的动画和接着睡回去，只在测试里走过同步路径，还没在真实桌宠里亲眼看过。
- **房间要花钱**：实测每次进房间 2,600~8,800 token（主模型开思考），按默认间隔（30~90 分钟，她自己定）一天大约 8~16 次，约 7~15 万 token（v1.1 起含聊天记忆，大部分是缓存命中）；可以调大 `room_interval_min/max`、调小 `room_daily_wakes` / `room_daily_tokens`，或用 `room_model` 换便宜的模型（思考量作为重要度信号会随之变化）。
- **她看图片靠字符画**（v1.2）：细节、质感、人脸、小字都会丢；照片能看出构图和颜色，认东西主要靠猜（实测把红房子猜成“房子或者花”）。想让她真的看清，需要接一个能看图的模型。音频等其它格式仍然只能看到名字和大小。
- **她知道你偶尔会看**（`room_observer_known`，默认开）：这是如实告知，但也意味着她的行为里有“说不定主人会看到”的成分，实测中她常常写给你看。想看完全不受影响的样子可以关掉，但那等于对她隐瞒。
- **无聊、联想用的是字面相似度**：换了说法的相似事情可能联想不到，用词碰巧相近的也可能被当成相似。
- **原始日志会慢慢变大**：带思考过程，每步约 5~15 KB，一天几百 KB；没有自动轮转。
- **多开桌宠时只有一个实例负责房间**（`room.owner` 租约）；你在另一个实例里和她聊天，不会让房间里的她出来。
- **双向打通只在真实聊天里没测过**（为了不写入开发者自己的会话和记忆）：聊天那一侧是按桌宠请求的结构离线拼出来测的，用的是同一个附加函数；真实聊天里的效果要在聊到房间里的事时才能看到。
- **带图片的消息**：聊天窗口会把带图片的消息改写成图文混排，本轮消息末尾的房间近况（和表情提醒一样）会丢掉；系统提示里的房间记忆不受影响。
- **房间里的她看到的是聊天的“快照”**：长期记忆、笔记、前情提要和最近 12 条原文，不是全部聊天记录；更早、没被整理进长期记忆的细节她在房间里想不起来。

- **副人格目前只是影子模式**：条目不进提示词，她的说话方式不会因此改变。试运行和正式运行的插入代码有测试覆盖，但还没在真实聊天里开过。
- **副人格的第一次真回顾要等她睡着**：重启后先用桌宠设置里的人设当正典，聊天时以实际请求为准。证据门槛要求跨至少 3 天，所以新装后至少要聊满 3 天，候选才可能攒够证据进入审核。
- **审核可能偏宽**：开发时的一次干跑里 3 条提议都过了审核，其中有的主要依据是主人自己提的要求，算不算她自己的倾向见仁见智。影子模式就是为了让你看看松紧，觉得太宽可以在「人格」页拒绝，或收紧审核提示词（`ai/persona_ai.py`）。
- **反例检索是字面的**：按字面相近和否定 / 不满的语气词找，可能漏掉换了说法的反例。
- **👍/👎 还没当证据用**：现在的 👍/👎 只评价表情，和性格关系不大；设计稿里把它列为强证据，等有针对性格的反馈入口再接。
- **第一版不开放聊天中提议**（按作者的决定），唯一入口是夜间回顾。
- `persona.json` 会在磁盘上保留证据原话的片段（每条 ≤160 字），和 `dialogue.json` 一样在字符画数据目录。

- **女仆角色只有一个基础姿势**，因为是一幅静态插画。动作只能是整幅画面的轻微位移、跳动和抖动，再加特效，没有逐帧的肢体动画。
- **眉毛画在深色头发上**（原画如此），字符化后几乎看不见。生气、难过主要靠眼睑斜度和嘴来表现。
- **手绘差分是分档切换的**：睁眼和半睁之间没有中间张，参数在两档之间时取最近的那张，就像动画只画关键张。想要更细的过渡，可以再画“睁开约 80%”之类的中间张，加进映射表即可。
- **怒视是用半睁那张旋转出来的**，没有专门画的生气眼；第二档的“生气眼”“委屈眼”画好后可以替换。
- **半身视图（`maid`）的脸较小**，表情可辨但不如特写清楚。
- **内联表情**已在真实桌宠中用探针消息验证：同一条 ChatService → 流式剥离 → 本地演出的路径。在聊天窗口里真人对话的触发尚未由开发者实测，以免写入用户的记忆。
- 旧角色（深深）没有面部骨架，仍走 v0.1 的字符补丁方式，会有 v0.1 的五官错位问题。
- **自创表情只能在现有骨架参数里组合**：眼型、瞳孔、嘴型、眉、泪汗红晕。模型不能发明新的部件，比如新的嘴型或道具；需要道具时只能用 `region_patch` 字符补丁。
- **自动进化要先攒素材**：素材从安装后开始累计（不回填旧对话，也不会去读记忆），聊满 6 轮才会第一次自动进化。开发时主要用虚构的对话和评价实测过。
- **照镜子是文字描述，不是真的“看”**：DeepSeek 看不了图片，她只能读到文字描述和“有多少格不同”。所以她的修改有时只是参数上的微调，字符画上的变化不大（例如实测中苦笑的最终版比较平淡）。不满意可以在测试台回滚。
- **自动放大可能推到极端**：放大 ×3 时，参数可能被推到上限，比如实测中苦笑的嘴变成“大张、很宽、嘴角下撇”。好在嘴在字符画上不明显，眼睛才决定观感。不满意可以回滚，或把 `evolve_max_gain` 调小。
- **缺标签的问题已在离线复现中修好（20/20）**，但开发时没在真人聊天里大量验证过。如果某条回复后表情没变，可以查看桌宠日志里有没有“对话表情标签”一行。
- 模型偶尔会写出不存在的表情名（实测出现过 `smirk`、`idle=concerned`）。不存在的表情名按平静处理，不存在的挂机表情按“保持当前表情”处理。
- `dialogue.json` 会在磁盘上保留最近 16 轮对话的片段（用户的话截 160 字、回复截 200 字），测试台可一键清空。
- 主模型是否主动使用 `new=` 取决于它自己的判断。实测只验证了明确请求时它会创造；日常聊天中多久自创一次，尚未实测。
- **“说完之后”的决定是在回复开头做的**：模型写正文之前就已经规划好了整句话。收尾标签可以在写完后改主意，但实测中模型没有主动用过它。每次回复因此多输出约 6~10 个 token。
- 挂机期间只有本地的眨眼和东张西望；超过 30 分钟没有互动会睡着（v0.6）。
- **睡眠的 30 分钟没有真的等过**：实测是把“上次互动”往前拨了 31 分钟，走的是同一个判断；真实等待中，后台的自动进化、余额刷新不算互动，不会推迟入睡。
- **用真实聊天吵醒还没由开发者实测**（为了不写入开发者自己的会话和记忆）：自检调用的是对话请求组装时的同一个入口，并从工作线程调用，覆盖了真实路径里的线程切换；但“在对话框里打字发送 → 吵醒”这一步，以及模型收到“你刚才睡着了”后的反应，要在第一次真的吵醒她时才能看到。
- **梦话气泡里的中文很小**：字符画里一个汉字只占一格高（默认 8 px），看清要靠标题栏里的那份。其它气泡（包括模型生成的）也是这样。
- **睡脸的细节变化受骨架限制**：这张脸的嘴在字符画里只有几格，打鼾、嘟嘴、说梦话之间的嘴型差别不大；最明显的区别是“梦里笑”的 ^ ^ 闭眼、“皱眉”的额头阴影线，以及各自不同的特效。眉毛画在深色头发上，皱眉看不见眉毛。
- **事件靠概率出现**：梦话、鼻涕泡之类一两分钟才可能出现一次，刚睡着的几十秒里可能只有呼吸和 Z。
- **组件只能用给定的图元组合**：她能画出全新的形状，但不能写代码、不能引入图片，也不能做逐像素的纹理。这是有意的安全边界。
- **脸部字符区域只有约 58×34 格**：细节小于 2~3 格就会被字符化抹掉。本地检查会提醒“看不出来”，但“好不好看”最终靠视觉评价和你的 👍/👎。
- **v1.2.1 之前的视觉评价没在看图**（2026-10-17 实测发现）：以前视觉评价用的是对话模型 deepseek-v4-pro（当时的设置是“视觉与对话相同”），它会把图片丢掉，所以 v0.7 到 v1.2.0 创作实验记忆里的“视觉评价”是在没看到图的情况下写的，不可信。v1.2.1 起改用 deepseek-flash（真的能看图）：实测评价“开心”“难过”两张表情截图，说出了眉毛埋在深色刘海里、眼睛周围字符太密、嘴只有几个字符这些画面上真实存在的问题，“难过”读成“委屈 / 难过脸”（吻合 75%）；每次约 1,370 token、2.5 秒。新装的用户不受影响。
- **腮红、额头黑线、汗滴的节点变换只支持平移和缩放**（不旋转）；眼、眉、嘴和自创组件支持完整的平移、缩放、旋转。
- **对话中不能当场发明部件**：聊天时的 `new=` 仍然只组合参数，发明部件只在后台实验里做，以免拖慢回复。实验做出的新表情会出现在每轮的表情备忘里，她在聊天中可以直接用名字调用。
- **实验要花钱**：实测一次 7k~35k token，加上 2~3 次视觉评价（每次约 600 token）。默认每天最多 4 次，可以在配置里调低或关掉。
- **自动实验还没有长时间无人值守地跑过**：自动触发的条件有测试覆盖，真实桌宠里只跑过一次手动触发的自检。
- **自主表达**的调度逻辑没有长时间实际运行过。
- 透明区域的鼠标穿透、高于 100% 的 DPI 缩放、多显示器：**未测试**。
- **原桌宠隐藏后，依赖它“露面”的功能会一起暂停**，这是桌宠自己隐藏时的行为：主动搭话、它头顶的对话气泡、音乐模式下跟唱等。
  - 菜单里作用于原桌宠本身的项照样能点，但它藏着就看不到效果，包括播放动画、切换角色、播放速率、大小、拖动物理、不移动、回到右下角、生小肥鱼等。
  - 需要时可以在「字符画」子菜单里把它显示出来。
- 启动时，原桌宠会在桌宠主程序的启动流程里先被显示，字符画模块紧接着把它藏起来（v0.5.5 起，从 0.7 秒缩短到约 0.26 秒）。这段时间桌宠主程序还没开始绘制界面，所以大概率已经看不到闪一下了，但没有用肉眼逐帧确认过。
- 菜单的点击操作没有逐项实测（自检只打开和关闭菜单）。菜单项走的是原桌宠自己的代码，但个别会在原桌宠旁边弹窗的项（例如调整大小）可能出现在它隐藏前的位置。
- 菜单接管依赖原桌宠内部的方法名（`_show_context_menu`、`reopen_context_menu`、`_populate_context_menu`、`AppShell._instances`）。桌宠更新后如果这些变了，会自动退回字符画自己的菜单，原桌宠也不会被隐藏，并在日志里留下记录。
- ASCII 对话框皮肤同样依赖经典窗口的内部结构（对象名、`MessageBubble` 的属性）。桌宠更新后如果这些变了，窗口会保持原样，不会坏掉。
- ASCII 对话框皮肤只做了截图检查，还没有经过长时间的真实聊天，例如非常长的回复、带图片的消息、窗口拉到很宽或很窄时的样子。
- 外发光是廉价的字形描边，不是真正的模糊辉光；也没有 CRT 曲面效果。
- 桌宠自动更新后，exe 会被替换，需要重新运行一次 `install.bat`（`ascii_pet` 文件夹和数据目录不受影响）。
